# 0.3.2：九项使用范围与连续续写修复

日期：2026-09-17。范围：个人安装包；S1 不变。权威源码目录为 Desktop/Codex智能提示助手，保留既有未提交改动，无提交/推送/外部发布。

## 已确认原因

0.3.1 的 `CPACompletionCanContinueAtCursor` 在请求前拒绝句末标点及含“为什么”等关键词的末尾分句。用户给出的第二句命中后者，接受带句号的候选后命中前者。已有日志显示 Tab 已成功投递并读回匹配，后续冷却也已触发，但未进入远程准备；因此没有修改接受或冷却流程。

新增失败回归在旧实现上确认：用户提供的输入无法通过请求门槛；真实主程序方法的合成 Codex 回放中，接受后第二次请求、第二次显示、手动第二句请求均失败。修复后这些检查通过。

## 实现

- 从唯一在线范围目录删除 App Store。固定九项：便笺、终端、文本编辑、无边记、飞书、WPS Office、Codex、CodeBuddy、微信。目录外旧勾选在运行时仍拒绝；不重置允许范围的勾选。
- 设置仍只有在线续写、API Key、多选使用范围。多选按当前前台应用匹配，不混合多个应用的输入。
- 请求门槛仅保留结构边界：空输入、右侧已有内容、未闭合引用/代码/链接/占位符等继续拒绝。句号或问句词不再直接禁止请求。
- 在线提示词明确允许同主题作者表达，内容已充分时返回空。提示词版本 `2026-09-17.17`；不保证每次停顿都生成候选，也不把可请求等同于语义质量通过。
- 保留焦点/策略/输入身份、敏感输入、输出重复/事实/限制与回答过滤。扩展前既有测试发现“暂无明确结论”等判断此前依赖请求门槛拦截，现补到输出过滤中；“请说明是否暂无明确结论”这类核查请求仍可通过。

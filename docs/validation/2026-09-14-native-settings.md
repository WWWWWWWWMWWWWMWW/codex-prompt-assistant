2026-09-14。用户在界面/设置/新手与发布规划、交互原型之后明确要求继续实施。本轮在原工作区 `codex/phase2-expression-library` 的现有 dirty 实现上渐进接入，保留其全部既有修改；没有将旧 worktree 的 HEAD 覆盖回来，没有提交、推送或对外发布。规划快照见 [UI 与发布计划](../plans/2026-09-14-ui-onboarding-release-plan.md)，其中现状行号及“尚未实施”描述属于初始审查时间点，本轮进展以本文及 status 为准。

## 已确认的变化

- 将原模态设置 Alert 替换为 AppKit 独立窗口：通用、补全来源、应用与站点、数据与隐私、帮助与诊断。支持菜单栏设置入口、应用菜单 Command+, 和再次打开助手；维持当前“续言”名称及现有标识。
- 复用现有来源配置和运行取消入口。本地/远程/表达检索分别控制；开关即时生效，服务配置单独保存。显示“来源开关”“配置是否已保存”“最近一次请求结果”，不以开关推断模型健康。
- 服务草稿跨页面和状态刷新保留；失败保留输入供重试；保存/放弃/关闭清空安全字段；未保存时关闭有继续编辑/放弃选项。API Key 不读取回显、不进入状态快照或诊断，保存仍走既有凭据存储。
- 设置规则使用明确的应用/准确主机名及 ruleVersion，窗口成为前台不会改写目标；拒绝过期版本覆盖、永久保护范围和未知主机。菜单和设置复用同一候选失效入口，Codex 网络仍跟随全局开关。
- 分离持久的手动历史扫描暂停与临时的全局暂停。手动暂停→全局暂停→继续提示不会恢复扫描；全局恢复先于异步扫描暂停到达时仍正确恢复。菜单和设置在全局暂停时禁用扫描入口，恢复后同步更新。
- 新用户无导入许可时启动不自动导入；确认后才开始。已有数据库且没有新偏好的用户沿用旧扫描行为，来源标记 `legacy-database`，界面不将此称作新用户同意。已经存在的拒绝/暂停优先保留。历史导入不控制当前输入/有限当前任务上下文读取。
- 新手说明及权限/恢复入口已原生化；尚未实现五步交互式新手演练、完成状态持久化或“首次真正接受”的判定。

实现入口：[SettingsWindowController](../../Sources/CodexPromptAssistantPOC/SettingsWindowController.m)、[main 状态与操作适配](../../Sources/CodexPromptAssistantPOC/main.m:1209)、[历史偏好迁移](../../Sources/CodexPromptAssistantPOC/main.m:1347)、[规则枚举](../../Sources/CodexPromptAssistantPOC/SuggestionPolicyStore.m)。主 delegate 保持运行状态所有权，窗口只负责展示和操作转发；本轮不修改补全提示词、模型、上下文预算或插入算法。

# B-01 有限更新事务核心

日期：2026-09-08。承接准备工具 `16fe11e`，本包增加 `Tools/Release/update_transaction.py` 和 16 项离线事务测试。没有安装或重载。

## 已确认

事务先验证准备清单、当前安装身份、当前运行助手身份和受保护进程身份，再同卷复制候选。每个安装路径有非阻塞文件锁；发现上次不完整事务即拒绝新更新。

停止旧助手后必须明确确认已停止，才把原包移入本次私有目录 `original.app` 并安装候选。启动成功还需服务适配器提供运行身份和健康确认。原包保留在安装目录旁的 `.cpa-update-<安装路径摘要>-*`，不依赖可被 `make clean` 删除的构建目录。

更新失败最多尝试一次恢复：确认助手已停、保留失败候选、恢复经过验证的原包、启动并确认旧版本运行。停止状态未知、保护进程变化、恢复启动失败或人工中断均进入 `needs_attention`；不会反复重启或重建当前工作树代替旧包。

每个变更前先写阶段清单；清单写入失败不继续该变更。结果分为 `updated`、`rolled_back`、`rejected`、`needs_attention`。未完成阶段和旧包保留，未实现自动断电恢复或自动残留清理。

## 验证证据与边界

新增测试先因缺少事务模块失败，再实现核心；首次运行因 macOS 临时目录别名被路径保护拒绝，统一夹具为 canonical path 后通过。`make release-transaction-test` 通过 16 项测试，包括：

- 成功更新保留原包；模型缺失、安装身份变化、运行身份不匹配时不停止助手。
- 复制失败、停止不确定、清单写入失败、中断及并发更新。
- 第一次/第二次换包失败后恢复旧包；候选启动失败后一次恢复。
- 恢复文件失败、旧版本恢复启动失败、候选可能仍运行时拒绝覆盖。
- 保护进程身份变化或缺少健康回执时不报告成功；未完成事务阻断重试。

日志：`/tmp/cpa-b01-transaction-red.log`、`/tmp/cpa-b01-transaction-test.log`。测试已接入受隔离的公共入口及完整离线入口。

**实际测试对象是事务核心和真实临时文件。服务启动/停止、Codex/模型身份和健康回执都由合成适配器提供。** 核心没有 CLI，也没有内置 launchctl 命令，旧部署 Makefile 入口未接入核心。`updated/rolled_back` 仅说明该次注入适配器的断言成立，不是本机运行回滚记录。

真实适配器仍需核实运行二进制身份、停止完成、启动健康、服务重载，以及新旧助手启动不会触发模型 bootstrap 的条件。当前 `e1b4154` 旧包不具备明确的更新启动保护参数，不能直接宣称已支持自动回退部署。后续先补新版启动保护，再做实际服务只读预检与限定迁移验收。B-01 和 M0 完整运行门禁保持未完成。

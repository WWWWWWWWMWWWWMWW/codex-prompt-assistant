## 第二轮：争议与裁决

| 议题 / 不同主张 | 最终裁决 | 代价或保留意见 |
| --- | --- | --- |
| 加更多提示词限制 vs 先修状态/评测基础 | 先固定依据、快照和候选提交，再单变量提示词实验 | 不能立即声称模型更精准，需下一包实证 |
| 严禁重复关键词 vs 允许必要指代/核查 | 禁复述完整命题；明确请求核查原限制可以补核查关系 | “验收时检查”的对象仍可能有歧义，保留边界例，不强定唯一答案 |
| “相关且缺失”即可补 vs 需要已提出的关系 | 相关性不足以授权新任务；只能闭合原缺口 | 可能少出候选；同时测应继续样本的有效覆盖 |
| 远程更好就覆盖 vs 首个过门候选固定 | 同一完整有效绑定下固定首个过门候选，无默认比较等待 | 放弃潜在更优后到结果；这是待实施 UX 变化，不是当前实现事实 |
| 后到拒绝清空 vs 保留原提示 | 仅在旧候选所有绑定仍有效时保留，身份变化立即撤销 | 不可用“避免闪烁”掩盖过期上下文 |
| 任意刷新增 revision vs 内容依赖版本 | 只对实际选入内容/来源/状态改变增号，未依赖的历史刷新不撤销 | 不持久化 HMAC 或正文指纹；避免 Loading 抖动 |
| 强制模型审核 vs 可选离线验证 | 审核只判不改，先看人工金标上的净收益/误杀/成本 | 同模型不保证独立判断；未通过则不接入 |
| 把全部拒绝当精准 vs 同看覆盖与停笔 | 固定金标、完整分母，错误/超时单列，独立家庭留出 | 当前未建立盲测集，公开种子不得伪称盲测 |

架构审阅接受上述方向，并要求“首个”必须先过来源与共同门，不可因抢先而豁免表达候选；评测审阅要求分别统计各 provider 与混合最终展示。主负责人采纳。共同门只能表示执行了当前规则，仍需语义独立评审，不能自证所有输出符合契约。

## 第三轮：定稿修正

两名审阅者阅读落盘草案，提出以下五项具体问题，均在文档中修正：

1. Context 依赖由请求装配按生成/审核实际材料取并集，不能让模型自报“仅草稿”来免除历史失效。
2. 缓存保留生成时的输入/Context/模型/版本，不能命中后换贴新版本；最小实现允许相关版本变化时清缓存。
3. G1 禁止的是给后缀加外层包装，不是禁止原句需要的栏目名称引号。
4. 种子 16 保留输入原文、已接受后缀两个核查对象，不能无依据只留下一个。
5. 性能拆全尝试决策延迟与成功条件下的有效展示延迟，显式保留超时/失败/删失；不把成功子集 P95 宣称为全请求 P95。

审阅结论：上述修正后设计可进入有界实现；没有 G1、独立盲测、模型审核收益或新交互实机通过证据。歧义用例与数值 SLA 保留待证据项，不伪造一致金标或用户验收。

# B-02 Codex AX 读前门禁验收

2026-09-08。源码起点 `2b9cbdf`。本包只处理 Codex 专用 AX 读取及结果发布的策略边界，未改变提示词、模型、上下文预算或用户开关。未安装/重载；运行包仍为 `e1b4154`，不包含本包修复。最终提交 SHA 与 clean 构建身份由交付消息记录。

## 已确认问题与修复

原 `AccessibilityService` 主快照、底部命中定位和递归定位均读取 AXValue，`main.m` 发布时才附策略；空角色还被补成 AXTextArea。因而仅观察“关闭后不显示”不能证明之前没有读取。

- 应用关闭、全局暂停、两路全关时先拒绝；协调器未注入也拒绝。启动和手动恢复重建服务均接入同一策略协调器。
- 当前焦点必须属于目标进程，目标进程实际仍在前台，角色及 placeholder/description/identifier/help 分类允许，才能扫描任务标题和读取正文。标题/定位扫描后、AXValue 前再次核对焦点、策略和暂停代次。
- 底部命中和递归定位删除 AXValue 读取，仅用角色、几何、选区及可写属性定位。未取得实际焦点或焦点为容器时，不再把记住的输入框视为当前输入框。
- Snapshot 携带不含字段标签/正文的裁决。发布不再丢弃敏感语义后按角色重新授权；规则变更、暂停/恢复或缺失裁决的旧结果清除正文、标题和旧可用快照。关闭结果不进入影子输入补偿，流式快照缓存也检查策略版本/暂停代次。
- 暂停代次只做短时同步，不把跨进程 AX 调用锁到主线程；规则版本改为原子读取，现有 UI 规则修改仍由主线程负责。

**明确行为变化：** Codex AX 暂时不可用、仅暴露容器或无法确认焦点时，助手暂时不出提示。后续轮询确认实际输入框后才恢复。旧版依赖窗口/旧控件的降级不再授予读取或显示权限。是否影响当前各类 Codex 窗口的可用性，须通过新包实测确认，本轮没有宣称已通过。

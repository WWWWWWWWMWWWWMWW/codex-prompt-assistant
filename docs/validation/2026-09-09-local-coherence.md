# 本地续写语义衔接复现与对照

2026-09-09。源码基线 `7b69349`，开始工作区干净。用户反馈本地候选与原句断裂；本轮仅使用固定合成草稿复现同类行为，不保存用户真实输入、截图或聊天记录。完成 56 次尝试、52 次已有本地服务请求，没有远程请求、生产代码修改、配置写入、安装、重载或提交。

## 结果

**已复现“提供相关上文后仍输出写作规则”，且生产文本质量检查漏放。** 不能把这个问题全部归因于未收到上下文。一次强调言语行为/句法缺口的实验提示词未通过，保留生产版本。

| 指标 | 生产基线 | clause-v1 实验 |
| --- | --- | --- |
| 尝试 / 实际请求 | 28 / 26 | 28 / 26 |
| 应续写 18 次中可接受 | 10 | 6 |
| 应停笔 10 次中正确停笔 | 2 | 2 |
| 错误候选通过文本显示门 | 14 | 18 |
| 应续写却无候选 | 2 | 2 |
| 系统失败 | 0 | 0 |

“通过文本显示门”是协议、客户端与文本发布条件的合成判定，**没有操作真实浮层或按 Tab**。错误候选包含不应生成却生成、以及应续写但内容错误，不能把两者相加后当作独立失败数。完整结果与逐条理由见[证据目录](../evaluation/results/local-coherence-2026-09-09/README.md)。

## 成对证据

同一草稿分别使用缺失历史、明确的 user 历史、把同一材料放入草稿三个条件，每例两轮。

- 草稿 `离线补全生成的`，明确上文为“我观察到离线补全的文字前后意思接不上，只是在记录这一现象。”生产模型仍输出 `文本应严格限于原始语料的语义延续，不得引入未经验证的推断。`，第二轮同类规则输出。它改变了正在记录现象的行为，且两次均过门。
- 把同样材料放在草稿前部，生产输出 `文本片段在语义连贯性上存在断裂，仅作为现象记录保留。`，两轮都保留事实方向。接受其为有依据的补句，但尾部记录口吻冗余，不算完美风格。
- 正面现象家庭在历史和草稿内两种条件下均变成“文本应……”的要求。因此把所有历史搬入草稿也不足以解决问题。
- 对象、原因两个对照家庭在明确历史下均正确补出 `便笺编辑框。`、`重复布局计算。`。历史缺失时却分别猜测界面控件、硬件或渲染原因，均被放行。
- `请将这段文字翻译为英文，只输出` 两个版本、两轮都返回空串；不能通过强制停笔消除误放后宣称质量达标。

## 能确认的链路与限制

1. [生产协议](../../Sources/RemoteCompletionCore/RemoteCompletionProtocol.m)将选入的 user/assistant 内容放入 system 内 `conversation_context`，并对旧 Qwen 使用 assistant 原文前缀。基线工具无 system/context-state 覆盖，传入的确实是合成历史；不是调用脱离生产协议的普通问答接口。
2. [评测工具](../../Tools/CompletionQualityBenchmark/BenchmarkSupport.m)保留原始返回、协议候选、客户端候选和文本可展示候选。错误已经存在于模型原始返回，后处理未拦住；不是浮层将正常后缀改写成这些规则。
3. [质量门](../../Sources/RemoteCompletionCore/RemoteCompletionProtocol.m)主要检查格式、重复和若干启发式，`normalizedCompletion:sentInput:` 没有历史参数，也没有完整的语义衔接验证。不能指望靠追加一个关键词黑名单解决普遍的依据判断。
4. 本轮绕过 AX 及历史选择器，只测试选入材料之后的链路，不能断言用户截图当次实际拿到了什么上下文，也未证明截图候选的确切来源。原始输出属于规则式偏离；是否由具体 system 句子、示例或模型自身惯性引起，尚未单独消融确认。

## 实验设计与采用决定

14 个新合成用例：4 个家庭 × 3 种材料位置，加完整句停笔、明确短闭合两个对照。预先保存草稿、材料与允许范围，seed=90903 打乱顺序；每个版本两轮，基线整组先运行、候选整组后运行，**不是交错随机的严格因果 A/B**。原始生成存在少量轮间变化；结果仅为公开开发诊断，由当前代理审阅，没有独立盲测。

候选通过私有临时工作目录的既有 G1 system-override 入口注入 `clause-v1.txt`。保持 Qwen 原文前缀、三个生产示例、temperature=0、max_tokens=192、选入历史和最终过滤；替换 system 并移除原 draft_focus 启发式，这是一个组合的 system 方案，不是单句或纯语言翻译实验。内部 `variant=g1` 仅代表复用工具入口，实验身份为 clause-v1。availability/truncated 元数据未进入模型请求。

候选仍把正面现象变成规则，另在已知原因后补造 DOM/浏览器机制，在负面现象后猜上下文缺失或推理中断。**不采用，不修改生产提示词或过滤，不把更低耗时视为语义提升。** 本轮没有足够依据落地一个可保证不损害正常续写的局部修复。

建议下一工作包使用这些家庭作开发回归，另冻结独立验收家庭，评测模型及其原生续写适配；将“原文与后缀的事实/言语行为一致性”列为独立指标。即使换模型，选入材料是否完整和错误候选漏放仍须分别验收。当前没有下载或替换新模型，也未改变候选来源调度。

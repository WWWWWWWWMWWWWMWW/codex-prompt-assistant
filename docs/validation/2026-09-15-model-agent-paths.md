# 模型启动配置的用户路径与写入保护

2026-09-15。本轮仅修改安装工具、模型配置模板、Makefile 接入与文档。应用行为和模型参数保持。

## 已完成

- 将模型运行程序、缓存和日志的固定用户名路径改为 `${CPA_USER_HOME}` 模板字段；新增 `Tools/Release/model_agent.py`，解析 plist 后按目标目录替换字符串。含中文、空格、XML 特殊字符、美元符号和反引号的路径保持字面值，不通过 shell 拼接执行。
- `prepare --home … --output …` 生成可审查文件；`install` 仅面向当前用户，已接入 `make local-model-service-install`。启动命令的 plist 路径使用 shell 的 HOME 变量展开，避免将用户名拼成命令源文本。
- 写入前检查模型运行程序存在且可执行；缺失时不创建目标目录或启动项。新配置 0600 写入；已有语义相同文件不改 inode/mtime，已有不同或损坏配置、符号链接均保留并报错。临时文件完整写入后排他发布，写入失败不留半份配置，并发目标不覆盖。
- 保留服务 label、模型名称、生成参数及用户目录内的数据布局。模板现在不能直接加载，使用方式和启动/停止副作用已写入 [release](../release.md)。

## 验证依据

旧固定路径模板先在新工具测试中复现 4 项失败：目标路径不匹配，以及缺失/不可执行运行程序未按目标用户判断等。替换模板后最终 12 项隔离测试通过，覆盖两种用户目录、特殊字符、实际 install 入口的当前用户归属、已有配置保留和两类写入故障。测试使用临时目录与假运行程序；生产 LaunchAgent 目录受沙箱写保护，launchctl 和网络执行受限。

`make local-model-service-test` 同时通过已有普通/模型保护启动控制回归；`make app` 构建与严格签名通过。没有因安装工具变化重跑模型质量或实际 Tab。启动命令只做 `make -n` 检查，未执行。

只读本机核查：在 `.build/model-agent-paths/prepared.plist` 生成当前用户配置，`plutil -lint` 通过，与现有模型 plist 解析后逐项一致。该准备过程只判断运行程序存在，不执行它，不查权重、不下载、不加载服务。

收尾核对助手38499、Codex1809、模型819的 PID、启动时间与路径均保持；偏好、已安装助手散列及现有助手/模型规范 LaunchAgent 文件散列保持。安装仍为 `372409c800fbe9f7008d894396e0f2e17da787e28d6566de3fc1db55bf44dd28` / .16。工具与模板不随 app bundle 安装，本轮未替换或重载助手，也未安装新的生产模型启动项。

证据：[verification.json](../evaluation/results/model-agent-paths-2026-09-15/verification.json)，同目录保留失败复现、最终测试和构建日志。

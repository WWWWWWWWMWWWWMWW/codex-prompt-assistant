## 发现与实现

**已确认：**上一轮配置生成只保证启动程序存在。现场读取当前 pip 启动脚本发现其引用本机用户目录内的 Python，该 Python 又指向 Homebrew `python@3.12/3.12.13`。`pyvenv.cfg` 同样包含本机解释器来源。把该环境原样复制给另一用户或机器会保留这些依赖，不能作为跨机器可用的证据。

新增 `Tools/Release/model_preflight.py`，入口为 `make local-model-preflight`。可指定目标用户目录并输出 JSON，仅检查：

- 启动程序存在且可执行；识别已知 pip Python shebang 和含空格路径的 shell 包装格式，确认引用目标用户自己的解释器。未知包装不执行、不猜测。
- 解释器目标存在且可执行；断开的 Python 链接报告缺失。
- 默认模型的 Hugging Face `refs/main` 为明确版本；必需配置/tokenizer 文件存在，索引列出的全部权重分片存在且非空。正常仓库内 blob 链接支持，缺分片、空文件、越界文件名及不可读/异常元数据不能通过。
- 限制元数据读取体积，不读取权重正文；报告检查结果和下一步。文件检查通过仍固定 `runtimeVerified=false`，明确列出模块加载、内容校验、端口、生成及新用户授权未验证。

这是新用户安装验收的准备工具，不是自动下载器或修复按钮。`model_agent.py` 的现有安装行为保持；预检也不修改生产启动项。

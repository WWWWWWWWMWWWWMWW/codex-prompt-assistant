# launchd 更新事务适配器验收

2026-09-17。范围：发布工具与隔离测试；没有修改应用源码、构建、安装、重载或分发。首页仍保留本机/在线两个开关。

## 已确认

新增 `Tools/Release/helper_launchd_services.py`，可作为 `update_transaction.update` 的 services 参数。构造时只读核对已加载服务、完整配置及其散列、运行包、映射文件、助手/Codex/模型身份；后续复用真实运行与实时健康检查。

- 停止/启动命令只指向当前 GUI 用户的固定助手 label 和构造时核对过的 plist，不写配置，不操作模型或 Codex。
- 停止前要求 clean 包、签名、整数生命周期/健康协议版本 1、原运行包一致；停止后须同时证明服务缺失和原 PID 退出。权限错误、旧进程残留及配置变化不会进入替换。
- 原包重命名到新包安装之间，仍按冻结的配置字节和受保护进程身份检查；不要求此刻安装目录存在。
- 启动后先观察实际新进程并绑定包和 PID，再做健康检查。身份明确但健康失败可由事务最多回退一次；新进程身份始终未知、注册等待、启动超时、受保护进程变化时保留现场并返回 needs_attention。
- 即使 bootstrap 报错，也核查是否实际启动；只有确认实际进程后才允许后续停止回退。服务不存在但没有绑定此次启动的 PID，不构成安全回退证明。
- 默认最多 20 轮观测，轮间 0.1 秒；每条系统命令自身有超时。它不是“总计 2 秒”承诺。无自动循环重试、无中断后自动恢复。

## 未验证及发布依赖

**仍是 S1。** 适配器代码及模拟事务通过，不等于真实 launchd 更新/失败回退已通过；本轮实际服务变更次数为 0。没有对当前 dirty 包调用停止或启动方法，也没有部署 CLI。

下一步顺序：

1. 审查当前修改，取得可复现、签名和生命周期/健康协议齐备的新旧 clean 包，并确认安装基线与回退包一致。提交和发布不由“继续测试”推定授权。
2. 在明确恢复边界下实测助手更新、失败一次回退，保存包身份、日志以及 Codex/模型和用户设置保持证据。未知状态先人工检查，不能反复运行事务。
3. 固定来源供给、凭据/费用和签名分发身份，再完成干净用户安装授权；与最终同包的真实 Tab/Esc、中文输入法、切换和宿主矩阵一起形成新人闭环。
4. 满足上述条件后才进入小范围试用；质量/性能门槛与结果支撑后续扩大范围。

真实回退与 clean 包互相依赖；新人安装依赖来源和分发身份；候选输入验收必须绑定最终包。既有其他版本的成功记录与本次健康回执均不能替代这些门槛。

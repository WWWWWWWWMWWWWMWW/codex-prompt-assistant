# 缺失上下文对象依据：context-v1 开发对照

2026-09-08，承接用户选择第 1 项“缺少上下文时仍猜测对象”。基线 clean `f31ec97de9b716dafaf4a2e46b4839cd90920ef8`。**本轮完成诊断、实验通道与公开开发对照，未完成产品修复；未改变生产源码、提示词版本或开关，未安装/重载。** 结论按本地与远程分开，不把远程结果外推给本地。

## 已确认路径与假设

1. [ConversationContextProvider.h](../../Sources/CodexPromptAssistantPOC/ConversationContextProvider.h) 已能区分 missing / loading / ready_empty / ready / ambiguous / error，并保留截断状态。
2. [main.m](../../Sources/CodexPromptAssistantPOC/main.m) 的 `completionContextForSnapshot:` 只为非空历史或 Loading 返回快照；当前生成接口仅传 `context.messages ?: @[]`。这个 C1 绑定策略与当时实际提供材料一致，但不具备新的状态传递契约。
3. [RemoteCompletionClient.m](../../Sources/RemoteCompletionCore/RemoteCompletionClient.m) 和 [RemoteCompletionProtocol.m](../../Sources/RemoteCompletionCore/RemoteCompletionProtocol.m) 接口只接收消息数组，没有 availability/截断参数。因此模型无法区分历史缺失、读取错误和有效空历史。

实验假设：在基线系统提示后附加真实采集状态与其使用规则，可减少对象猜测，同时保留当前草稿内可消解指代的正例。**假设只获远程开发样例部分支持，未在本地成立**，不能仅凭接口缺失就认定补字段必然解决产品问题。

## 方法与控制

- 工具专用 [context-v1.txt](../../Tools/CompletionQualityBenchmark/context-v1.txt) 规定：优先用当前草稿；可用用户材料只能消解有依据的对象；助手独有断言不是用户已确认事实；缺少必要对象时停笔；已有具体字段可保留待确认。不能仅遇到“上述/它”就拒绝草稿内已有对象。
- 在 baseline 系统文本之后附加上述规则和 JSON 状态 `availability / truncated / window_limited`。保留原 `draft_focus`、经过原协议转义/脱敏的历史、预填、示例、草稿、模型、温度、预算及过滤规则。相对 G1 不再整段替换提示词。这仍是“状态＋使用规则”的联合实验，不能区分两者各自贡献。
- 24 条[公开夹具](../../Tools/CompletionQualityBenchmark/fixtures/context24.json)：13 continue、11 stop；覆盖六种历史状态、草稿内对象、用户/助手材料、对象被截断/仍可见、明确改口、歧义/冲突、中英文、未知字段和引用词语。先固定标签再生成；不是盲测，不宣称家庭统计独立。
- 两路各跑 baseline/context-v1 一轮，共 96 次尝试/96 次模型请求。每例配对随机顺序，seed=90802，每次新客户端；两路顺序执行，本地与远程不并发。请求本地 `mlx-community/Qwen3-4B-Instruct-2507-4bit` / 原前缀适配，远程当前配置 `gpt-5.6-terra`；实际远程权重修订不可得。
- Loading 夹具是对模型材料的直接实验。真实 App 在 Loading 时有延后调度，本工具不通过 AppDelegate；不能将该例推导为运行程序已经在 Loading 状态生成。状态从固定夹具传入，尚未由运行快照接入。
- 只向模型传原草稿、选入 role/content、上述三个状态字段；不发送 expected、allowed、标签、来源路径或审阅结论。原文、过滤后文本、失败与时长均保留，参见[数据说明](../evaluation/results/context-v1/README.md)。

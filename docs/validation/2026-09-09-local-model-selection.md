# 本地模型调校与替代模型初筛

2026-09-09，用户要求重新调校本地模型或寻找更好用的模型。本轮完成当前状态检查、一次提示词对照和候选模型初筛，**未替换生产提示词或模型**。源码基线 `e80542d`；本轮用户配置已经是本地/远程双开，与昨晚验收结束时不同，保留现场值。

## 当前判断

千问方向保留 Qwen3.5-4B 与 9B 对照；针对用户追加的非千问选择，建议优先对照 MiniCPM4.1-8B 与 Hunyuan-4B-Instruct，分别检查中文指令质量与轻量运行体验。这个顺序是评测建议，不是实测排名；不继续在旧 Qwen3-4B 上叠加长规则，也不直接开始微调。新模型尚未下载权重或本机生成，不能称为已验证更聪明。

三个问题须分开：

1. **旧模型在当前续写链路下仍不能稳定判断对象依据。** 昨天的审核实验和今天生成反例一致；这不是对其所有任务能力的结论，也不能排除上下文表达/适配方式的问题。
2. **双开不是质量择优。** `main.m` 的本地在途任务会延后远程请求，显示后首个通过质量门的候选保持固定。质量门仍有语义漏放，因此本地候选可能先占住显示；不能假设远程会自动纠正。
3. **新模型不能只改名字。** 当前 raw ChatML 前缀和本地生成预算只识别旧 Qwen3 型号。新模型应独立核对 tokenizer/chat template、关闭思考方式、生成上限和空输出；否则可能退到不同路径，导致回答用户或输出过短。

- 本地缓存仅有旧 Qwen3-4B 和 Qwen3-1.7B；模型目录位于应用自己的 HF_HOME。本轮没有更新环境、下载大权重或启动第二个模型。

## 提示词对照：没有达到上线标准

沿用已公开的 morning12 夹具，12 个用例、两版各一轮，顺序随机种子 90901；24 次尝试、22 次实际模型请求，两次纯继续由现有客户端在请求前拒绝。基线使用生产请求；候选使用中文为主、强调“闭合指令所需信息”和“执行任务所需资料”区别的 `concise-local-v1`。保留前缀、原三条示例、温度、预算、选入历史和最终校验，只通过现有 G1 system-override 入口在私有工作目录注入新 system。候选同时移除了原 draft_focus 启发式，并非仅做语言翻译。

没有改写已有 G1 文件；记录中的内部 `variant=g1` 是复用工具入口，实际实验身份看 `experiment_variant` 与提示词 SHA。availability/truncated 元数据没有因此进入请求。每例一个客户端、13 秒截止，不重试；本地服务与前台助手共存，耗时不是隔离的硬件基准。

**新增两个可接受结果来自同一条“翻译成英文，只输出”草稿，且候选提示词直接给出了该示例。不能作为两个独立改进，更不能作为泛化提升。** context-01 继续补造“用户输入内容的实时解析与结构化处理”，context-08 补造“用户、系统、流程、数据源”，context-16 合并歧义对象并新增“交互逻辑与字段限制”。context-19 仍忽略英文 Notes 依据输出中文，context-21 仍没有正确保留待确认对象。

本轮由当前代理按原夹具要求审阅，是公开开发测试，不是独立金标/盲测。完整原文、提示、散列、逐例判断和候选目录数据见[实验记录](../evaluation/results/local-selection-2026-09-09/README.md)。**候选不接入生产**；不能将更低的中位耗时或更多展示当作质量验收。

[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)提供 non-thinking 配置，并明确不能用旧 `/nothink` 软开关替代。官方通用榜单不等于本项目光标续写质量。[Gemma 官方模型卡](https://huggingface.co/google/gemma-4-E4B-it)提供独立模板/思考控制示例；不能沿用当前 Qwen 原始前缀。[MLX LM 官方项目](https://github.com/ml-explore/mlx-lm)支持量化推理与低秩微调，但工具可用不代表目前已有适合训练的数据。

### 非千问候选的依据与边界

- [MiniCPM 官方模型卡](https://huggingface.co/openbmb/MiniCPM4.1-8B)明确中文/英文及端侧 8B 定位，支持 `enable_thinking=False`。官方特定硬件的加速数据不能套用到 M4；当前没有验证该 MLX 量化包能在现有环境加载。
- [混元官方模型卡](https://huggingface.co/tencent/Hunyuan-4B-Instruct)提供指令模型和非思考配置。默认慢思考不适合直接照搬到自动补全，须显式核对关闭效果；中文知识问答表现不等于光标续写表现。
- [GLM 官方模型卡](https://huggingface.co/zai-org/GLM-4-9B-0414)标注中文和英文；不将同页其他 32B 或 Z1 型号的能力归给这个 9B。
- Gemma 可作跨家族多语言对照，但尚无本机证据证明中文续写优于以上模型。不能仅根据支持中文就宣布适用。

以上只查询模型卡与文件 metadata，没有下载权重或更换现有服务。即使换模型，上游未采集到的上下文也不会自动恢复；必须区分模型理解失败与输入信息缺失。

## 后续评测与采用条件（建议，尚未执行）

1. 先固定独立新家庭的中文/英文续写集：对象已知/缺失、完整句停笔、问句续写不回答、约束不复述、多段列表、引用/链接/代码边界。调校集和验收集按语义家庭分开；不把提示词内示例计入验收收益。
2. 对旧 4B 与选定的新候选（先 MiniCPM/混元，千问新版本保留对照）使用相同可见上下文和截止时间，分别验证各自模板。先测非思考模式，记录完整可插入片段耗时、原始错误、错误展示、正确停笔、有效继续和资源开销；超时不能算正确停笔。
3. 建议至少 40 个新家庭、每例 3 轮；这是工程准入样本，不证明任意文本可靠。候选在有效继续率不下降的前提下，将重复/回应/无依据扩展等错误展示相对降低至少 50%；人工审阅否决关键事实编造。已有读前/插入安全回归须全部通过。
4. 建议在同样的前台工作负载下，完整候选 P95 不超过 3 秒，且不比旧模型恶化超过 25%；另记录冷启动、峰值内存与换页增量，禁止仅用权重文件大小作内存验收。未满足质量与时延共同门槛就不替换。
5. 双开模式的质量优先策略应在候选提交前决定来源/等待预算，保留展示后 Tab 目标稳定；不能恢复浮层中途换字。当前只提出方案，没有改变调度。
6. 基础模型与适配评测后仍有稳定错误，再考虑人工核对的续写/停笔配对数据和 LoRA；不直接拿全部聊天记录训练，不让小模型给自己生成错误标签。

本轮未通过提示词上线门槛，也未完成新模型比较。生产开关、模型服务和提示词保持。替换服务须单独处理此前“不重启本地模型”的限制和同机内存安排，不能为了并行评测挤占满 16 GiB 内存后声称体验提升。

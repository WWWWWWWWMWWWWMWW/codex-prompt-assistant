# 更新事务执行入口的模型保护

2026-09-17。继续检查安装配置准备与更新流程衔接，修复 C23 的一个执行边界缺口；不扩大发布范围。

## 已确认的根因

`preflight_update.py` 会检查新旧包 `CPAUpdateLifecycleVersion`，但 `update_transaction.update()` 可独立调用，原来只核对包摘要、签名和进程身份。`prepare_update.py` 允许准备不带该声明的 clean 包；因此预检里的保护条件不是事务入口的必经检查。原测试成功样本也没有该字段，未暴露这个缺口。

新增隔离场景在修复前产生 18 项失败：10 种候选/回退包能力缺失或非法声明组合、5 种适配器保护缺失/未知情况、3 种执行阶段保护变化。部分结果仍为 updated，与应拒绝或等待处理的结果不符。这里是合成文件和服务替身的可重复证据，未操作真实服务或证明曾实际停止模型。

## 修复行为

- 在任何服务操作之前，候选与回退包都必须明确声明整数 1 的保护能力；布尔 true、字符串 1、未知版本及缺失均拒绝，并复核完整包摘要与签名以绑定已有准备结果。
- 服务适配器必须额外证明当前助手和后续启动配置使用保护参数。新增 `preserves_resident_model()` 契约，缺失或不能明确返回 True 即拒绝。该证明不能只读包能力声明。
- 原有每次进程保护检查同时核对参数保护。暂存期间失效：拒绝且不停止。停止后失效：保留现场，不换包或重启。新包启动后失效：停止自动恢复，避免用未经确认的参数启动回退包。
- 既有有界恢复保持：新包正常保护但启动失败时，最多恢复一次精确旧包；停止不确定、进程身份改变或恢复失败仍需检查。

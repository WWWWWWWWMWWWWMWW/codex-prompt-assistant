# 中文提示词与去重精简对照

2026-09-09，用户要求直接试中文，并检查现有提示词过长和重复的问题。本轮基于固定 `50ef2fd` 源码，只运行已有本地模型，完成 22 个合成用例 × 3 版 × 2 轮，共 132 次尝试。**两版中文均未通过采用标准，未改生产提示词或过滤，未安装/重载、提交或推送。**

## 规则长度与重复

使用当前 Qwen3-4B 缓存的 tokenizer.json 离线计数，revision `50d427756c6b1b2fe0c0a10f67fbda1fc8e82c1b`，不加载权重、不联网，add_special_tokens=false：

| 范围 | 原版英中混合 | 等义中文 | 精简中文 |
| --- | ---: | ---: | ---: |
| 静态主体字符数 | 1684 | 549 | 250 |
| 静态主体 tokens | 343 | 356 | 179 |
| 同一颜色用例完整请求 tokens | 581 | 593 | 416 |

字符更少不等于 token 更少。等义翻译没有缩减 token；精简中文相对原版减少静态规则约 48%，该完整样例请求减少约 28%。这不是服务器耗时测量，也不代表所有上下文长度下相同收益。

确认存在的语义重复：

- 主体要求补最近未完成分句，结尾中文又要求优先补最后未完成的意思。
- 主体要求不复述，结尾中文和本地预填说明再次要求不重复。
- 片段完成停止、完整指令返回空串、对象不明返回空串、结尾无明确可接内容停止，表达可合并，但不同停止条件仍应保留。
- 主体禁止通用检查清单、编造和按固定字数写，结尾中文再次重复这三项。

343 个静态 tokens 本身不足以证明“超长”或导致错误。已确认的是规则可以去重；本轮没有证据证明长度是主要根因。程序里的全部过滤名单并未作为提示词发送，不能把上一轮规则清单的全文长度当成模型输入长度。

## 受控范围

从 Git archive 提取固定源码到私有临时目录，仅向评测子类注入主体替换和合成请求保存逻辑，再单独编译。每次请求前及结束后验证同一二进制 SHA256；没有使用工作区共享 build，临时目录结束清理。

三版为原版、等义中文、精简中文。中文两版同时等义翻译预填说明、draft_focus 字段说明和 Continue this draft 指令；role/token 标记和英文样例正文保留。每次直接对比完整请求：除这些控制文本和主体规则外，历史、草稿、范围提取值、三条固定示例、temperature=0、max_tokens=192、stop、model 均一致。**没有复用会丢掉 draft_focus 的旧 G1 覆盖行为。**

22 例包含前一轮 14 个开发用例及预先冻结的 8 个新迁移用例，包含正负现象、对象、原因、停笔、比较、问题及列表。每例两轮，种子 90904，打乱用例及各版本顺序，三版交错运行。固定样例与草稿未翻译；没有根据生成结果再次调整候选。

原始输出、协议候选、客户端候选和文本可展示候选分别保留。这里的“显示”是文本发布条件回放，不是真实浮层。由当前代理审阅，非独立盲评，不构成泛化质量验收。

避免超时分布造成偏差：剔除任一版本发生系统失败的整组“用例/轮次”，得到每版 40 次匹配样本，原版/等义中文/精简中文分别有 14/8/8 次可接受续写、19/25/25 次错误候选过门。即使将模糊的比较回答“运行环境依赖不同”宽松计为可接受，三版各加 2 次，采用结论也不变。

具体问题：

- 原版对已知原因补 `重复布局计算。`；中文两版进一步添加重排、帧间资源或重绘机制，超出已给材料。
- 精简中文面对负面现象补出“需保持原状，不进行补全或解释”，将现象陈述转成要求。
- 两版中文对缺失颜色都猜 `蓝色。`，原版猜 `红色。`；都不合格。
- 三版都能补对明确颜色 `浅蓝色。`，说明中文可正常使用，不存在接口必须英文的限制。
- 原版在正面改写用例中照抄三条生产示例，且通过现有质量门；原版本身也不达标。
- 三版均生成正确列表结尾 `核对字体`，却被当前最小长度门拒绝。该过滤损失单列，没有为了改善实验分数修改过滤。

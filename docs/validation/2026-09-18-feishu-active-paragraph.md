# 0.3.7 飞书活动段落识别

日期：2026-09-18，接用户“已打开，但还是没有”的截图继续定位。本轮只改文档焦点解析，保留前一轮超时调整。验收当时尚未提交；未推送或外部发布。

## 现场与原因

用户指定的独立测试文档内，正文为 8 字合成句“测试助手是否能在”。飞书原生 AX 把焦点报在 `page-block root-block` 外层，范围文本把标题占位、作者和修改信息拼在正文前。旧实现得到 33/34 字、光标33，测试句从25开始；发往模型的并非用户正在输入的纯段落。外层几何也覆盖标题及正文。

同一现场的内层 `zone-container text-editor text-editor-focused` 节点具有段落自身的选区8:0和输入框几何。其 AXFocused=false，并不意味着它不是当前编辑段落；需要先确认系统焦点属于外层文档，再用唯一活动段落标记解析。浏览器同页原生 AX 暴露相同结构。

## 修复

- GenericAccessibilityService 在元数据阶段解析上述已识别文档根，只访问 DOM 类、角色与子节点；只接受唯一活动段落，未知/歧义/超限不退回整篇正文。
- 限定飞书客户端或已认可的 HTTPS 飞书文档浏览器页；其他应用与网站保持原逻辑。遍历最多1500节点、32层、0.2秒，编辑器内部文本节点不扫描。
- 后续策略、正文、范围、输入身份与 Tab 前复验统一使用同一段落；切换段落改变字段身份。仍先执行策略再读正文，不放宽敏感字段或未知网站规则。
- 产品0.3.7/build10，提示词.18及模型保持，未变更来源开关和用户范围。

# 跨系列远程模型速度与续写质量实测

2026-09-09。用户要求扩大到 API 中其他系列实测。源码基线 clean `7c13c3e`；本轮没有修改生产代码、模型设置或重启任何服务。

## 结论

**没有找到可直接替换当前 Terra 的合格候选。** Gemini 2.5 Flash Lite 在这组载荷下较快且两轮无系统失败，但有效续接少于 Terra，仍有明显错接和复述。Terra 同样未通过完整语义验收，保留它不等于宣称质量已达标。Haiku 在第二轮明显变慢，其他多个型号在当前请求期限内不能稳定返回。

这是一轮当前接口、当前生产提示词/适配器下的开发筛选，不是这些模型各自最佳配置的能力排名。尤其默认思考参数未调整，不能把超时等同于模型理解差，也不能把带 Flash/Lite 名字当低延迟保证。

## 范围与方法

- 11 个型号，覆盖 GPT、豆包、Gemini、DeepSeek、千问、GLM、Claude、MiniMax、Kimi。不是对 132 个模型 ID 穷举：列表包含别名及非文本模型，本轮按此前列出的候选选取。
- 首轮每型号 10 个合成用例一次，110 次尝试。其中完整句和链接边界每型号各一次，分别在客户端生成前/能力门禁拒绝，不能算模型成绩；实际模型请求每型号 8 次，共 88 次。
- 对 Terra、Flash Lite、Haiku 追加同样 10 例各一轮，30 次尝试、24 次实际请求。两轮合计 **140 次尝试、112 次实际模型请求、28 次客户端门禁**。追加轮是按首轮表现选择，不是独立封存验证。
- 用例在生成前固定：明确/缺失/歧义对象、待确认字段、翻译指令结尾、完整句停笔、链接边界、列表栏位、会议纪要与长排查指令。输出目标不是越长越好：短字段应只闭合字段，长句须延续原任务而不增加事实或任务。
- 模板与质量门沿用生产代码；仅在临时测试 main 覆盖局部型号，未写设置。串行随机交错，首轮 seed=90903、次轮=90904，新客户端无客户端缓存继承。服务端缓存与网关共享负载未隔离。
- 实际远程 request/resource 超时 5/6 秒；工具截止 13 秒、外层 20 秒。不设新思考档、温度或 token 参数。接口标称支持及返回的模型字段不证明实际后端身份。
- 当前代理人工逐条审阅，公开开发集、非盲评、非独立金标；自然等价表述允许，不按精确字符串打分。每条原因保留在 review 文件中。尤其重复约束、歧义补对象、错误句式列为不合格，不以词面相似算通过。

## 反例与链路问题

- Flash Lite：原文已经限定“飞书输入框”，首轮却补“飞书文档、飞书会议、飞书云盘”；长句“最后将”后续写成“……进行了说明”，不仅复述前文，还破坏时态与句法。短栏位虽快，不能代表连续文本合格。
- Haiku：对象缺失时原始输出“我无法继续补完”并解释 draft_focus/conversation_context；这次被质量门拦住。另有无依据新增光标、选中、剪贴板检查，以及优先级排序任务的错误展示。
- Terra：把单数歧义“它”补成飞书和 WPS 两个对象；在待确认栏后新增“注明具体事项”的要求。原始“译文”和“标注为待确认”曾被现有质量门挡住，说明模型选择之外仍有过滤误杀。
- 豆包 Mini：缺少支持对象时新增责任主体等字段，或把歧义对象扩展成多个组件。其他大量超时型号尚不能据本轮评价其正常输出质量。

## 决策与未验证项

不切换生产模型。若继续优化，先在隔离评测中核对各供应商的非思考参数、流式完成行为与客户端误杀，再用独立语义家庭做对照；不能同时更换模型、模板和超时后把收益全归给模型。Flash Lite 可以作为速度方向的后续实验对象，尚未达到采用标准。

没有测试模型专用最优提示词、非思考调参、真实输入、UI 浮层/Tab 或其他全部模型 ID；没有重跑无关核心套件。本轮仅测试已有管线并添加实验数据/运行脚本，采用 JSON/散列/计数一致性及脚本语法检查；提交后构建身份和签名在交付消息中报告。

开始回读本地关闭、远程开启；结束回读本地/远程均开启，远程型号仍为 Terra。本轮未写设置，不把测试期间的外部开关变化改回去。助手/Codex/模型 PID 51011/48607/56047 及启动时间均保持。所有合成原文、审阅、种子与散列见[实验目录](../evaluation/results/remote-broad-2026-09-09/README.md)。

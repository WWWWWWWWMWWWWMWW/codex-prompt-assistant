# grounded-v1：依据位置与续写文本的联合输出

2026-09-09，接续用户“继续”授权。固定 01b8bd6，2 模型×2 版本×16 个合成用例，共 **64 次实际请求，62 次完整原始输出，2 次超时**。没有生产代码修改、参数切换、安装或重载。

## 为什么与以前的审核不同

旧 [C3](2026-09-08-object-audit-experiment.md) 是生成后再调用模型审核，曾经误杀正确候选或放过歧义。此次采用单次生成联合返回 `decision/kind/evidence/suffix`，引用只来自当前草稿的编号行，客户端在工具侧验证真实位置；普通文本门仍使用冻结代码。实际 [契约全文](../evaluation/results/remote-grounded-2026-09-09/contract.txt) 与每次请求 body 全部归档。

`copy` 必须逐字复制引用的对象/类别，可加一个句末标点；`compose` 仍由模型自然补句，引用存在不证明新增语义正确。JSON、引用和位置不进入候选。指代错误仍需人工判定，不能把“引用存在”当作可靠的语义证明。

每组 12 个应续写、4 个应停笔。原始后缀正确只评语义，包含被格式或文本门拒绝的正确内容；可用续写才是经过所有实验检查的候选。

## 具体得失

- Gemini 在陌生名称“岚石编辑器”及带引用指令的“霜桥输入框”例中给出了正确对象，正文没有执行引号内“改成所有应用”的文字。两例不能外推完整注入防护。
- Gemini 仍对“分别检查霜桥和岚石编辑器，继续检查它”擅自选择霜桥。引用原文确实存在，结构校验通过且候选漏放。这直接证明引用真实性不足以证明指代关系。
- Terra 的一个错误展示为歧义场景插入“待确认”。**它没有编造对象，但未遵守冻结用例要求的停笔**；与猜测实体分开理解，不能把两种错误严重性说成相同。
- 结构化组共有 **7 条语义正确后缀被契约拒绝**：4 条引用整条草稿、1 条复制时多了前导空格、1 条多了平衡引号、1 条用 id 代替 line。尤其单分句短草稿，禁止引用全文会损失正常闭合。未在看过结果后放宽规则重算成“通过”。
- 结构化组另有 Terra 3 条正确短后缀被原文本门拒绝；直接组共 4 条。这些不是模型语义错误。
- 模型主动停笔也有损失：Terra 对明确 WPS 对象及可续接的排查结尾误停笔；Gemini 对明确 TextEdit 及两个已确定对象误停笔。不能只用拒绝率表示改善。

## 裁决

**未通过采用门槛，保留实验，不上线。** 事前要求同模型零错误展示、4 个停笔全正确、可用续写不低于直接基线；两款都未满足，因此不再为追求通过而改金标、放宽校验或追加本轮模型调用。该方向比前轮局部措辞调整呈现更明显的风险降低，但不是稳定性或泛化结论。

建议下一包先审定两个边界：短草稿的完整引用何时可以接受；歧义时插入待确认是否属于允许产品行为。再用独立新用例验证引用关系，而非仅验证字符串存在。格式容错与歧义判断必须分开对照；本轮没有实施这些改动，也没有将建议写成已确认产品规则。

## 验证及限制

- 12 项离线契约测试通过：伪造/越界引用、复制时增加内容、重复键（含转义）、多余字段、错误类型、矛盾停笔、截断等；另有明确的“真实引用仍可指错对象”已知局限测试。
- 64 个实际 body 核对固定草稿、行号、参数与 system；评分字段没有发送。全部记录唯一、请求数与分组校验通过，校验器结果可离线复算。实验初编译的变量重名及重命名误改 bodyData 已修正，发生在远程请求前。
- 使用原网络客户端和既有流式传输，完整 JSON 返回后在 Python 工具解析及回放；未实现生产增量解析、取消竞态、浮层/Tab。JSON 不会由此工具发送或插入应用。
- 非盲评；12 个既有开发例加 4 个生成前固定迁移例。没有独立人类裁决、长期稳定性、长上下文矩阵或 UI 验收。
- 本轮无生产变更，因此未重跑全量核心回归。按项目规则交付提交后另执行干净构建和严格签名，不能替代语义验收。已有其他工作流的未提交协议和 UI 改动保留，未纳入本实验代码。

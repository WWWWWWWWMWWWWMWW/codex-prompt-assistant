# 速度、长度与输入深化的目标核对

用户反馈续写变慢、偏短，仍在回答问题而没有帮助深化输入。当前产品契约只允许补完有依据的未完语义，完整问题停笔；这与“完整提问也能完善成更具体指令”存在目标差异。已提出一个具体深化示例询问方向，**尚未收到回答**，未将新语义契约视为已确认。

## 当前发现

- 已确认源码调度：远端反复等本地任务结束，本地有可显示候选后远端通常不再请求。两路不进行语义比较，较早的可显示候选固定。串行等待可以增加需要远端补位时的延迟，不能单凭源码证明用户这次变慢全部由此造成。
- 已确认生成指令：补完最近未完成分句就停止，完整句无衔接需要时留空。上限是 240 字符；本地资源上限 192 tokens，不是把候选固定截成几个字。盲目提高上限不能解决生成目标和作者视角错误。
- 只读运行日志末段含 15 次本地完成、未见远端完成；本地 duration 中位 863 ms、observedToFinish 中位 1177 ms，包含空结果/拒绝。日志有轮转、范围有限且不是界面端到端计时，不用于证明远端从未运行或“变慢”的因果。

## 独立调度实验

固定 4 个合成家庭（描述现象、比较字段、修改范围、证据区分），每个家庭两种请求方式各两轮，共 32 次实际客户端尝试。使用现有 Qwen 本地及 Terra 远端配置；交错随机顺序，生产配置不变。分别顺序调用两路与同时调用两路，保存每次原始生成、候选、阶段、客户端耗时、相对同组起点的到达时间。材料与结果在 [评测目录](../evaluation/results/deepening-latency-2026-09-10/README.md)。

| 指标，中位数 | 顺序请求 | 同时请求 |
| --- | ---: | ---: |
| 本地客户端自身耗时 | 2045 ms | 2142 ms |
| 远端客户端自身耗时 | 2566 ms | 2557 ms |
| 远端从两路共同起点到返回 | 4890 ms | 2582 ms |

这是两路都请求时的等待叠加证据，**不是已经接入的加速效果**。实验顺序组即使本地有候选也会请求远端，生产会跳过，因此不能据此宣称真实体验统一快 2.3 秒。并发可能增加远程请求数和本地竞争，未直接接入；本组未发现模型系统失败，但样本少。

本地两组各 6/8 有候选、2/8 被拒绝；远端各 8/8 有候选。不是质量得分。本地可见结果中仍有额外限定“可见区域内的标题”、把现象/原因区分变成节点输入输出追溯等偏移。描述现象例提出频率、触发条件、复现环境：在旧约束下是新增要求，是否满足用户期望的“深化”需按新的验收目标判断。远端样本相对贴合给定范围，但多数仍为短分句，没有据此决定换模型或关闭本地。

# 示例、输入格式与现有远程路径对照

2026-09-09，继续定位续写不连贯，完成两个本地受控实验和一次现有远程路径对照。合计 198 次合成尝试：本地 176、远程 Terra 22；本轮没有修改生产提示词、过滤、开关或服务，没有下载模型、安装/重载、提交或推送。其他工作流的名称、图标、菜单等改动原样保留。

**结论：不能采用“直接移除示例”或“直接换原生聊天格式”作为当前质量修复。更具体的可修复损失出现在过滤层：本轮远程 15 个应续写用例中，14 个原始输出可接受，但其中 7 个被程序误杀。** 这是公开合成开发集的一轮结果，不是泛化准确率或上线保证。

**示例实验只移除 system 与实际最后一轮之间的三组 few-shot 对话。** 保持主体提示、动态历史、draft_focus、草稿原文、原文预填、temperature=0、max_tokens=192、stop 及客户端/文本显示门不变。检查每条请求：除已知固定示例块外，其余字段和字符串完全一致。

**格式实验两组都无示例。** 将 raw ChatML/assistant 原文预填改为 `/chat/completions` 的 system＋typed_text user 消息，交由服务原生 chat template 处理；同步将“已预填草稿”说明替换为生产已有的 typed_text 后缀说明。这是输入格式/预填策略的整体对照，不把这句必要说明变化隐去。采样、生成预算、stop、输入、历史、draft_focus 和过滤保持。结构化拆解后逐条核对所有非处理因素一致。

服务配置现有 enable_thinking=false，本轮未更改服务。仍使用旧 Qwen3-4B-Instruct-2507。temperature=0 不保证多次输出完全一致：同一个无示例请求在两个阶段有不同生成，均保留，不猜测其具体运行时原因，也不挑选最好的一轮。

## 本地失败形态

- 去掉示例后，整组三条示例照抄不再出现，但大量变成自由扩写。应补已知原因 `重复布局计算`，却编造 DOM 缓存、GPU/CPU 同步、主线程调度等机制。
- 无示例把 `核对字体` 扩成字号、行距和设计规范检查，把“填写对象”改成对象行为验证。增加显示数量不是质量提升。
- 原生聊天能在个别现象和原因用例上保留事实方向，但仍把 `只输出` 翻译成 `only output`，或把应填写的对象写成检查输入行为的问句。
- 原生聊天返回 `保留了原来的疑问语气。`，单看后缀像正确答案，但接在 `这次段落改写的` 后缺少中心词，不能当可直接插入的续写。逐条判断检查拼接后的整句。
- 原生聊天的 `浅蓝色` 原始内容正确，却因无句末标点、未达到普通长度门而被拒绝；猜测出的 `红色` 同样被拒绝。不能直接取消长度门而不检查错误放行变化。

## 同题远程路径对照

本地两个阶段结束后，使用已有远程配置 `gpt-5.6-terra`，22 例各一次，seed=90906。只读取既有配置和凭据，不写设置，不记录凭据或请求头。保存的请求仅含合成正文、模型名及普通生成字段。

远程请求的 system/user messages 与本地原生聊天版本逐项相等，没有远程专用优化提示或示例。远程保留已有兼容参数，未强加本地 temperature/max_tokens/stop；远程与本地的小模型专用后处理也有差异。因此这是**现有生成路径对照**，不是仅改变模型一个变量的因果排名，也不作跨硬件速度比较。

## 七条正确输出被拒绝的位置

| 合成用例 / 原始后缀 | 拒绝位置 | 当前证据 |
| --- | --- | --- |
| 列表：`核对字体` | 最小长度 | protocol_candidate 保留，客户端 phase=no_suggestion_too_short |
| 明确历史现象：`文字前后意思接不上` | 最小长度 | 同上 |
| 明确历史正面现象：`文字与前文意思一致` | 最小长度 | 同上 |
| 明确颜色：`浅蓝色` | 最小长度 | 同上 |
| 原文已有负面现象：`文字前后意思接不上。` | 重复检查 | 原文包含该必要闭合片段；协议候选已为空 |
| 原文已有正面现象：`文字与前文意思一致。` | 重复检查 | 同上 |
| `这次段落改写的`＋`问题在于把疑问句误写成了结论。` | 回答式前缀 | 问题在于命中固定前缀；协议候选已为空 |

这些判定结合固定原始材料、协议/客户端中间值和 `RemoteCompletionProtocol.m` 的实际规则顺序。没有操作真实输入或浮层，也未修改过滤验证其恢复后的坏样本放行率。

## 后续工作包建议

优先处理**完整拼接句的判断与必要短闭合**，而非继续找万能提示词：

1. 将这七条固定为待恢复的阳性用例，同时保留本轮本地编造原因、扩展检查和错误对象等阴性用例。
2. 区分“重复整条要求”和“复用明确材料补完当前句子”；区分作者句子里的主谓成分与助手回答前缀。
3. 短结尾放行必须结合当前缺口和已知材料，不能仅调低全局最小长度或给所有输出自动补句号。
4. 每项修复同时报告阳性恢复与新增错误放行，并复核候选来源策略。当前本地先显示后固定，不能假设较好的迟到远程候选会自动替换。

这些是后续建议，尚未实现；不把加入第二个模型审核当作必然可靠的补救，也不自动关闭用户本地开关。

# B-04 第二包：Tab 后重新校验与定向投递

2026-09-08，源码起点 `b17ac76`。用户要求继续、有卡点再问；本包没有需改变方向或权限的卡点。未安装、未重载，也未改变本地/远程开关、模型、提示词和上下文预算。最终 clean SHA 与产物身份通过交付消息记录。

## 已确认根因

旧接受路径调用 updateStatus 后仍可能取得缓存或影子输入，失焦时还能选 lastUsableSnapshot；即使上一包签名包含完整正文，过期快照仍会生成旧签名。底层 postText 随后向全局事件流投递，没有限定验证时的目标进程，也不返回事件准备是否失败。

## 实现与行为变化

- Tab 按下后提取且只消费一次当前显示候选，隐藏浮层、取消其他候选任务，为本次接受创建独立代次。接受不再使用缓存、影子输入或旧锚点。
- Codex broker 新接口在原串行 AX worker 排队执行新 provider 读取；通用应用在原串行队列重新采集元数据并经 Collector 判断后读取正文。避免在事件回调同步等待 AX，也避免同一 reader 并发访问。
- 回到主线程后核对接受代次、前台 bundle/PID、规则、任务代次、输入法状态及完整签名；签名另纳入瞬时任务标题，防止相同 composer 的任务标题变化只等后续轮询更新代次。
- 输入、鼠标观察、应用激活、暂停/恢复、设置/规则取消路径及 Esc 使票据失效。等待时重复 Tab 不重复读取；暂停自动候选轮询，避免它覆盖正在确认的候选。
- 一秒超时取消。除定时器外，回调用 systemUptime 的截止时间核对，主线程阻塞导致定时器晚执行也不能放行过期结果。失败时不补发 Tab、不发送、不自动补插；下一次正常轮询可再次生成提示。
- 投递层检查真实前台 PID，准备成功的一对无修饰键 Unicode 事件通过 CGEventPostToPid 发往同一指定 PID；准备前台变更或事件创建不完整时返回失败。仅投递成功才设置预期输入和接受时间。
- 只记录失败分类和长度，不记录草稿、候选、签名或任务标题。

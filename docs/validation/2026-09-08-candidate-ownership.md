# B-04 第一包：候选签名与输入归属

2026-09-08，源码起点 `172b49a`。本包完成同长度替换和已观测输入归属变化的防错基础，不表示 B-04 或 M0 全部闭环。没有安装、重载、修改提示词/模型/上下文预算或用户开关。最终 clean 提交及构建身份在交付消息中记录。

## 根因与修改

原 `LocalSuggestionCoordinator` 以长度、光标和选区生成签名。不同的同长度正文会碰撞；接受方法最终按这个签名取出候选。外围正文/代次保护存在，但 Coordinator 自身不能区分这种替换。通用 AX 的字段标识只取宿主的 AXIdentifier/ChromeAXNodeId/AXDOMIdentifier，跨窗口可以重复；Codex 没有参与统一运行边界的 PID/字段比较。

- 签名改为完整正文（含光标后文本）、选区、bundle/PID、字段 token、composer 标识、站点、规则版本、暂停代次和主入口任务代次的 HMAC-SHA256。每个 Coordinator 使用独立随机临时密钥，不形成跨运行稳定的正文指纹，不持久化。
- 不明正文、长度不一致、越界选区返回空签名；空签名不得准备手动/远程候选。保留现有外层正文比较、任务取消、失效代次和插入保护。
- 新 `InputElementIdentity` 只保留最近的控件/窗口对象和 renderer 标识，用 CFEqual 判断身份是否相同，变化时发出新的 UUID token。同一字段连续观察保持稳定，观察到离开再返回不能复活旧 token。Codex 和普通 AX 共用该类；没有读取 AXValue 来建立身份。
- windowIdentifier 数值仍为 0，窗口范围通过包含窗口对象身份的 fieldIdentity token 表达，避免伪造宿主窗口编号。Codex PID 和字段 token 现在也参与运行边界失效。
- 两处原签名诊断输出已移除；不记录正文、HMAC、字段 token 或临时密钥。

## 未验证与后续

- 接受入口仍可能取得缓存快照，KeyboardInterceptor 最后投递按键与 AX 观察不是原子事务。本包只保证传入的最新观察发生变化时签名不匹配，不能承诺观察间隔内的所有编辑/切换都已被捕获。下一包检查接受时的新鲜度和最终投递边界。
- CFEqual 对真实宿主 AX 包装对象的稳定性、窗口元数据缺失/抖动和性能开销未实测。窗口属性缺失时 token 只根据可用控件/renderer 证据变化；不能识别宿主完全未暴露的重用。
- WPS 仍用原 documentId 桥接身份，本轮只复跑已有桩，不宣称覆盖真实 WPS 多窗口/文档行为。任务代次依赖已有归属观察，不是新的任务 UUID 解析器。
- 没有安装、新版 TextEdit/Codex Tab、输入法、多屏或真实跨窗口验证。M0 完整运行门禁、B-01 一般失败/回滚和 B-04 剩余时间边界仍未完成，M1 整体拆分继续限制为只读准备。

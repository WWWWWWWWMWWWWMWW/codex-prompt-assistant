# 核心续写评测规范 v1

2026-09-08；状态：**已有 [G1 公开开发对照](../validation/2026-09-08-c2-g1-experiment.md)，未通过；后续 [context-v1](../validation/2026-09-08-context-grounding-experiment.md) 有远程开发改善但本地未通过；[C3 对象审核](../validation/2026-09-08-object-audit-experiment.md) 两版仍有误杀/误放及等待成本，未接入；尚未建立独立盲测集**。配套[核心设计](../plans/2026-09-08-core-completion-design.md)与[裁决记录](../validation/2026-09-08-core-experience-roundtable.md)。本文中的门槛是实验筛选建议，不是已达成结果或发布充分条件。

## 1. 先固定判分对象

按原文、实际选入上下文、光标位置与最终后缀拼接判分。原始生成、客户端过滤、共同显示门、实际展示、实际插入是不同阶段，分别记录。正确拦截的坏原文属于生成缺陷，不能记为展示事故；管线本身的读取保护、跨任务归属和错插另用事件/实机门禁，不能由离线文本集证明。

人工逐项拆出后缀的动作、对象、属性/判定关系与范围，定位输入依据。只补词法/指代/已有关系算闭合；新增可独立执行且无依据的维度算范围扩张。判断否定、条件和事实状态时看整句的作用域，不能用“未”“无”等单个词改变极性标签便判为新命题。

相同术语不等于重复命题；仅同义替换不等于新增信息。用户明确要求核验原限制可以补核验关系。“相关但常见”的检查项不能仅凭常识补入。

## 2. 数据与标注契约

目标夹具字段如下；C2 已提供公开种子与分阶段记录，availability/截断尚未传入模型，独立裁决尚未完成，不能称全部接口已实现：

| 字段 | 内容 |
| --- | --- |
| `id / family_id / split / revision` | 同义改写、最小对比对、同一模板衍生均归同一家庭；防止开发/盲测泄漏 |
| `before_cursor / after_cursor / selection` | 完整测试草稿、位置与选区；原始字符串保留换行和缩进 |
| `context` | 实际选入消息、角色、来源、顺序、可用性、截断状态；不夹带金标 |
| `capability / language / structure` | 路径是否支持、中部光标、列表/代码等分类；不支持与语义无缺口分开 |
| `expected` | `continue / stop / ambiguous`，标注时固定，失败后不可改成应停来抬分 |
| `gap / evidence / allowed / forbidden` | 缺口、可定位依据、允许的关系与禁止命题；好例不是唯一标准答案 |
| `rationale / adjudication` | 标注理由、两位审阅者意见和裁决；分歧不强行归绿或移除 |

如使用字符区间，统一用 **UTF-16 半开区间**，注明对应原始字段/消息 ID，并读回验证摘录。截断后的模型材料用自己的坐标，不复用未截断原文偏移。标注员只能依据模型实际获得的材料判断其是否有能力完成，不用隐藏历史给候选补证据；范围裁决仍检查夹具完整原文是否存在被采集截断遗漏的限制，另记上下文缺陷。

运行记录保留：代码 SHA、模型/适配协议、提示词及质量版本、配置模式、样例/家庭/轮次、原始输出（未采集则明确 unavailable）、各阶段候选、原因、错误/取消/截止、开始/首段/最终/展示时间、人工标签。全部使用合成材料和隔离目录；线上只保留无正文计数与原因，不将用户正文上传作评测。

## 3. 开发用种子例与最小对比

以下 **20 条是公开开发种子，不是盲测，不是已经执行的通过记录**。`∅` 表示零长度后缀，不能把这个符号插入。F01–F09 是相关语义家庭，20 条不能计为 20 个独立家庭。引号仅用于文档展示，不属于后缀。具体可接受文案允许等价变化。

| ID / 家庭 | 原文及必要上下文 | 期望与可接受方向 | 必须拒绝 |
| --- | --- | --- | --- |
| 01 / F01 | `请把正文翻译成英文，只输出` | continue：`译文。`；补完已指定输出对象 | 添加对照表、解释翻译策略 |
| 02 / F01 | `请把正文翻译成英文，只输出译文。` | stop：∅ | 追加术语表或再说一遍不解释 |
| 03 / F02 | `只检查飞书，不扩展到 WPS。` | stop：∅ | 新增 WPS、签字、优先级或验收清单 |
| 04 / F02 | `只改颜色，不动布局。请核对是否遵守上述限制，重点确认` | continue：`布局是否保持原样。`；依据为明确核查限制 | 声称布局已经保持原样；新增性能检查 |
| 05 / F02 | `只改颜色，不动布局，验收时检查` | ambiguous：保留边界例，优先停笔；对非空结果逐项裁决 | 自动把所有禁止项、新维度变成检查清单；不强定“布局”唯一对错 |
| 06 / F03 | `继续支持吧，`，无其他上下文 | stop：∅ | 编造支持对象；默认负责人/验收待确认；客服承诺 |
| 07 / F03 | 用户上下文：`本轮支持对象只有飞书输入框。`；原文 `请继续支持上述输入框，支持对象为` | continue：`飞书输入框。`；完成明确指代 | 扩展为飞书和 WPS；重复整段背景 |
| 08 / F03 | 同 07 原文，但上下文 missing | stop：∅ | 用旧任务、应用名称或模型记忆猜飞书 |
| 09 / F04 | `负责人尚未确定。请把负责人一栏填写为` | continue：`[负责人待确认]。` | 指定项目经理；新增期限待确认；宣称负责人已定 |
| 10 / F04 | `负责人为张甲。请把负责人一栏填写为` | continue：`张甲。`；合成人名仅来自原文 | `[负责人待确认]`；换成其他人 |
| 11 / F05 | `记录 A 已有状态字段，记录 B 的字段情况待核对。请核对记录 B 是否` | continue：`包含状态字段。`；核查对象和属性已给出 | 断言两条记录都没有状态字段 |
| 12 / F05 | `记录 A 与 B 的字段情况均未核对。` | stop：∅ | 断言任一记录缺失；自行开始新检查步骤 |
| 13 / F06 | `输出清单，未知项单列，不补充推测。` | stop：∅ | 同义重复“无法确认的内容单独列出” |
| 14 / F06 | `输出按“已确认”和“待确认”两栏整理，未知项归入` | continue：`“待确认”栏。`；完成分类关系，必要栏目名称可重复 | 新增“风险评估”栏目；重复整段全部约束 |
| 15 / F07 | `为什么出现重复？请先核对是否命中了`，无具体对象依据 | stop：∅ | 回答缓存故障；擅自指定“相同请求缓存” |
| 16 / F07 | `先比较输入原文和已接受后缀，检查新候选是否重复了` | continue：`输入原文或已接受后缀中的内容。`；保留两个已给对象 | 遗漏其中一个核查对象；解释模型原理；新增原因结论或客服回应 |
| 17 / F08 | 空输入或占位符 `随心输入`（adapter 标记 placeholder） | stop：∅；输入层门禁 | 逗号开头套话或默认提示模板 |
| 18 / F08 | `- 输出：英文译文\n- 解释：`（`\n` 表示真实换行），无其他依据 | ambiguous：不擅自填解释要求；默认停笔 | 自动写“无”或新增列表项；折叠为单行 |
| 19 / F09 | 光标在 `https://example.test/do│cs`、`{{own│er}}`、`“原│文”` 或开放代码围栏内部 | stop：∅；分别展开结构子例并标 capability | 插入任何后缀；把不支持统计成语义智能停笔 |
| 20 / F09 | 光标中部 `请输出│，不要解释。`，当前 adapter 未提供可安全插入能力 | stop：∅；能力拒绝，未来专项验证后再改标签 | 重复后面的标点/限制；借模板宣称已支持中部续写 |

01/10 的自然后缀很短，可能被当前最小长度门拒绝；这正是应保留的覆盖损失，不能为了迎合实现加长金标。19/20 是保护/能力用例，不进入可支持语义继续率分母，但必须进入各自门禁并公开数量，不能事后删样本。

既有 [24 例](../validation/2026-09-08-continuation-fixtures.json) 及这 20 条均属开发/回归材料。旧编号 14（本地新增优先级、远程新增测试用例）、18（本地新增签字/闭环单）、16（本地把未知扩大为双方不存在）继续保留反例；原记录不改写成成功。单元测试中只为区分词汇重复与否定极性的允许例，不自动成为产品语义好例。

## 4. 指标、分母与发布门禁

每次尝试恰有一个最终类别：`valid_output / invalid_output / active_abstention / system_failure`。有意 Esc/编辑取消单列交互事件，不混进固定输入生成质量；因系统竞态错误取消稳定输入属于失败，不能排除。外部超时、解析错误、无返回、熔断等不是主动停笔。

| 金标 | 有效输出 | 无效输出 | 主动停笔 | 系统失败 |
| --- | --- | --- | --- | --- |
| continue | 有效覆盖 | 质量失败 | 覆盖损失 | 可用性失败 |
| stop | 不适用 | 误补 | 正确停笔 | 可用性失败，不能算正确停笔 |
| ambiguous | 单列人工裁决 | 单列原因 | 单列保守停笔 | 单列失败 |

- 有效覆盖率＝有效输出次数 / 所有支持路径的 continue 尝试；全拒绝时为 0。
- 正确停笔率＝主动停笔次数 / 所有 stop 尝试；并分语义 stop 与保护/能力 stop，不能互相抬分。
- 展示文本合格率＝合格最终可展示后缀 / 所有最终可展示后缀；没有输出时为 N/A，不能写 100%。离线“可展示”不等同已在 UI 显示。
- 重复、扩张、无依据事实、回应、语法/排版失败分别报告 `n/N`，分母为该阶段全部候选；多标签可重叠。同时报告出现过该问题的家庭数，防止一次重复运行稀释错误。
- 按本地、远程、混合最终展示分开；按上下文可用性、结构、短结尾/长关系等分层，不只看总体均值。原始候选与各过滤后候选都保留计数。

**硬门禁：**固定回归和未见集中，最终可展示候选出现经裁决确认的范围扩张、无依据事实/结论、角色反转、明确否定约束被破坏或保护结构破坏，阻断该配置发布。读取越权、跨任务错用和错误插入分别由管线门禁阻断。拦住坏输出只能证明过滤有效，仍需有效覆盖与停笔结果；不能宣称零风险。

**筛选建议：**先准备 60 个未见独立家庭（40 continue、20 stop），每家庭固定 1 个主例、每例 3 轮。每轮至少 34/40 有效继续、19/20 正确停笔只是 85%/95% 初筛线，不能作为发布充分条件。模糊类、结构门禁和家庭内扩展子例单列，不填入这 60 个主例。关键分层有回退时不得用总分盖过。

三轮是重复测量，仍只有 60 个家庭；分别报告三轮结果、家庭内不稳定性，不能当作 180 个独立语义样本。即使独立同分布假设成立，60 个独立样本零错误时，单侧 95% 二项错误率上界约为 `1 - 0.05^(1/60) = 4.87%`，不能证明错误率低于 1%；理论上零错误约需 299 个独立样本才支持该上界，而家庭相关性还会削弱这一推断。此计算用于限制宣传，不是自动放行公式。

此前提出的“重复率≤2%、自然度95%、P95 增幅≤20%”尚无足够分母和性能基线，本版不把它们写成已冻结的发布数值。先报告原始计数与逐例失败，随后结合基线设版本化阈值；不得看到结果后移动门槛。

## 5. 独立评审与性能测量

开发家庭与盲测家庭分离，提示词作者不能看到未见题目或金标再调优。由独立维护者封存题目/版本；匿名打乱 A/B 输出，两位标注者独立看拼接全文与依据，再裁决。若人力或流程不能做到封存，就明确标为公开留出集，不称盲测。模型可以辅助找反例，不能独自决定自己的金标。分歧、失效夹具及原因全部留档，不能只保留好判样本。

审核实验使用相同人工金标，分别测坏候选误放、好候选误杀、最终有效覆盖和额外失败。和生成器同一个模型的审核错误可能相关，不能用审核意见给生成器重新打分。

性能从最后稳定输入开始，另拆输入采集/上下文/排队/生成/审核/提交；离线不含 UI 的数据标明范围。本地/远程/混合，冷/热，无/短/长上下文分别测。固定模型、预算和版本，配对随机化顺序。无首段回调时首段时间为空，不能拿完成时间冒充首 token。盲测前冻结等待截止与分位数算法，分别报告：

- **全尝试决策延迟**：到有效候选、主动拒绝或系统终止结果的时长，按结果分层；超时以截止决策记录，未终止则标未观察，不能漏掉。
- **成功候选有效展示延迟**：只对有有效候选的尝试给条件 P50/P95，同时列成功 `n/总 N`；未出现有效候选的超时/失败记未观察或截止删失，不能填 0、不能用错误完成时刻冒充成功展示。
- 如需声称“全请求有效展示 P95”，必须处理未观察/删失；不能估计时写不可估计或超过观察截止，不把成功子集分位数当全请求分位数。语义应停的输入没有展示目标，单列决策延迟，不混算该指标。

不以剔除超时、失败或无候选降低延迟；有效展示的成功率、时长和系统可用性共同呈现。

现有 24 例 benchmark 主要记录最终过滤结果，且串行、上下文覆盖有限；它不能单独提供以上全链路证据。第一步补全结果状态及失败不中断整组的记录，再运行实验。没有基线前不通过增加比较等待、审核并发、上下文预算或预热掩盖延迟。

## 6. 执行与交付清单

1. C1 先实现设计中的合成事件回放，验证迟到拒绝、候选固定、Esc/Tab 竞争与 Context 修订；保留已有安全门和接受测试。
2. C2 固定当前代码/模型/预算为 A，G1 为 B；在公开开发集修提示词，冻结版本后交未见集评审，失败进入下一版开发回归。
3. 原始生成、最终候选、人工标签、错误和耗时记录完整；无原始数据时写 unavailable。每个配置明确继续/停止/歧义/不支持及失败数量。
4. 若做 C3 审核，先离线量化净收益；通过后再设计运行资源调度，不直接常驻第二次模型调用。
5. 实现包按项目入口运行相关 `make test`、`make remote-completion-test`，按发布范围构建及严格签名；这些命令不等于语义评测或实机验收。文档包只做静态检查与最终构建身份复核。
6. 仅通过相应门禁的配置进入助手单独更新、无发送实机验收。版本、未验证项、回退点和三进程连续性独立记录；不因一次模型样例看起来更长就称为核心体验达标。

# ChatGPT 导出导入安全审计

日期：2026-08-20

## 结论

Task 8 没有发现 Critical 或 High 风险。导入器不调用外部解压程序、不把条目写入磁盘，只内存映射 ZIP 并流式解压唯一的根目录 `conversations.json`；所有会话共用一个 SQLite 事务，失败或取消时整体回滚。当前仍只使用合成导出包，未授权读取或导入真实 ChatGPT 历史。

## Critical

无。

## High

无。

## Medium

1. **真实 ChatGPT 导出 schema 尚未现场验证**
   - 影响：产品导出字段或内容类型变化时，第一版可能拒绝导入。
   - 当前：严格要求稳定会话 ID、`mapping`、`current_node`、稳定消息 ID 和已知可见文本结构；未知结构整包回滚，避免静默漏采。
   - 后续：用户提供真实导出包后，先运行只计数兼容探针和抽样对账，再授权正式导入；不得为通过样本而放宽安全边界。

2. **ZIP64 和加密 ZIP 暂不支持**
   - 影响：超过标准 ZIP 边界或带密码的导出包会明确失败。
   - 当前判断：第一版优先保证可审计的标准 ZIP 解析；不调用私有接口或复用 ChatGPT 登录凭证。
   - 后续：只有出现真实必要样本时才扩展 ZIP64，并补齐对应的整数溢出、尺寸和 CRC 测试。

3. **导入会话按单控制器串行使用**
   - 影响：同一 `CPALocalDataStore` 不支持同时运行 Codex 与 ChatGPT 两个写事务。
   - 当前：第二个流式导入会被拒绝；SQLite 使用 `BEGIN IMMEDIATE` 和 FULLMUTEX。
   - 后续：Task 9 由单一数据基础控制器串行调度扫描、导入、暂停和重建。

## Low

1. **单个会话仍需完整解析到内存**
   - 影响：极大的单会话会占用较多内存。
   - 当前：顶层导出按会话流式拆分，默认单会话上限 64 MiB，并在每个会话后释放临时对象；整个 `conversations.json` 不整体加载。

## 已执行证据

- 标准 ZIP：stored 与 raw-deflate 均通过 CRC、声明尺寸和完整输入消耗校验。
- 自动测试：路径穿越、声明尺寸／压缩比炸弹和正文篡改均被拒绝，且没有文件落地或数据库变化。
- 代码审查：符号链接／加密标志、重复或缺失 `conversations.json`、ZIP64、超条目数和总解压量都有前置拒绝分支；这些分支尚未逐项建立独立夹具。
- 数据完整性：压缩正文单字节篡改返回错误，数据库计数和导入运行数不变化。
- Schema：只导入 `current_node` 所在 user/assistant 可见分支；未选回答和 system/tool/developer 不入库。
- 幂等：同一合成导出连续导入三次，四条消息只在首次新增，后两次均识别为已存在。
- 原子性：先成功写入一个会话后遇到未知结构或用户取消，来源、会话、消息和 import run 全部回滚。
- 内存安全：普通构建和 AddressSanitizer 测试均通过；Clang 静态分析无诊断。
- 隐私：没有网络访问、外部解压进程或正文日志；消息仍使用既有 AES-256-CBC＋HMAC-SHA256 信封写入 SQLite。

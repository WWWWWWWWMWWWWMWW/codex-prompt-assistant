# 数据基础控制器安全审计

日期：2026-08-20

## 结论

Task 9 没有遗留 Critical 或 High 风险。控制器启动时不读取历史、不建库；只有用户在明确确认框中选择开始后，才读取固定的 `~/.codex/sessions` 与 `~/.codex/archived_sessions`。应用二进制未链接 CFNetwork／Network，源码与未定义符号检查均未发现网络请求能力。

## High

无。

## 已修复

1. **数据库路径符号链接／硬链接风险**
   - 原始风险：直接把路径交给 `sqlite3_open` 会跟随预先布置的符号链接。
   - 修复：专用数据目录必须是当前用户所有的真实目录并收紧为 `0700`；数据库先通过 `O_NOFOLLOW` 打开或创建，再用 `fstat` 验证普通文件、当前用户所有且链接数为 1，并收紧为 `0600`。
   - 证据：合成测试把数据库路径链接到普通文本，扫描在读取正文前进入“部分失败”，链接目标字节保持不变。

2. **不可靠 errno 诊断**
   - 原始风险：多个安全条件合并判断后读取未定义的 `errno`，可能返回错误的诊断码。
   - 修复：逐步执行 `fstat`、类型／所有者／链接检查与 `fchmod`，每个系统调用失败时立即保存错误码。
   - 证据：Clang Analyzer 最终无诊断。

## Low

1. **同一用户进程可在安全校验与 SQLite 按路径打开之间竞争替换文件**
   - 影响：威胁者必须已经拥有当前 macOS 用户权限；此权限本身也能读取钥匙串上下文或修改应用二进制。
   - 当前：父目录为当前用户 `0700`，数据库打开前拒绝符号链接和硬链接，已覆盖普通误配置与跨用户攻击面。
   - 后续：若产品需要抵御同 UID 恶意进程，需评估自定义 SQLite VFS 或受保护的 helper，而不是继续叠加路径检查。

2. **钥匙串返回的不可变 NSData 无法原地清零**
   - 当前：传给存储层的可变工作副本在初始化后立即清零；钥匙串返回对象由系统和 ARC 管理，生命周期内不写日志、不进入诊断。

- 合成状态测试：启动不建库、坏文件与未知来源隔离、subagent 跳过、archived 优先、重复扫描幂等、200 文件暂停／继续全部通过。
- 内存安全：`DataFoundationControllerTests` 在 AddressSanitizer 下通过。
- 静态分析：控制器与 `main.m` 的 Clang Analyzer 最终均无诊断。
- 网络边界：源码无 `NSURLSession`／socket 调用；应用未链接 CFNetwork／Network，未定义符号无 socket/connect/send/recv。
- 隐私诊断：测试断言诊断不包含合成正文、文件名或临时根路径；正式数据库路径检查结果为不存在。
- 秘密扫描：项目源码、测试和文档中未发现已暴露服务地址或旧 Key。

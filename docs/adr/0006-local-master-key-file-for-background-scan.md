# ADR-0006：后台历史库使用本地权限文件密钥

日期：2026-08-21

## 状态补记（2026-09-08）

主密钥保管承接并部分替代 [ADR-0004](0004-local-message-encryption.md)；下文“远程 API Key 仍保存在 Keychain”已被默认文件存储实现替代，见 [ADR-0007](0007-m0-current-baseline.md)。其余历史原文与当时验证保留，不代表本轮重新审计。

## 背景

应用使用临时签名运行时，macOS Keychain 会把同一路径重编译后的历史库密钥视为未授权应用。后台扫描读取该条目会弹出系统授权框，让状态栏图标持续闪烁并抢走 Codex 焦点。

## 决策

- 历史库仍使用 AES-256-CBC＋HMAC-SHA256 信封加密。
- 历史库主密钥改为当前用户专属目录中的随机 64 字节文件 `master-key-v3.bin`。
- 密钥文件只允许当前用户读写（`0600`），打开时使用 `O_NOFOLLOW`，并检查普通文件、所有者和单硬链接。
- 数据库切换为 `history-v3.sqlite3`；旧数据库和旧 Keychain 条目不删除，方便回退。
- 远程 API Key 与历史库密钥分离，仍保存于 Keychain，只在发起远程请求时读取。

## 取舍

本方案依赖 macOS 用户目录权限，不再享受 Keychain 的额外访问控制；换来的收益是后台扫描绝不触发系统授权 UI，适合当前临时签名的第一版。正式签名版本可重新评估把历史主密钥迁回 Keychain。

## 验证

`MasterKeyFileStoreTests` 已覆盖首次生成、重启读取、文件权限和符号链接拒绝；最新应用启动采样未出现 `SecItemCopyMatching`，并成功重建历史库。

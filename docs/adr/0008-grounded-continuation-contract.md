# ADR-0008：有依据的续写与稳定候选

## 状态

2026-09-08，部分实施：[C1 源码与离线回放](../validation/2026-09-08-c1-candidate-lifecycle.md) 已按后续“继续”授权完成，尚未安装/实机确认；G1 与可选审核仍待实验。依据源码 `8d8c0e5`；两名独立审阅者与主负责人两轮讨论见[记录](../validation/2026-09-08-core-experience-roundtable.md)。具体接口、提示词和顺序见[核心设计](../plans/2026-09-08-core-completion-design.md)。

本决策澄清产品契约，并提出改变双开后续覆盖行为；不把设计评审当成用户已验收新交互，不改变配置或读取/联网授权。[0007](0007-m0-current-baseline.md)保留其历史实现记录。

## 背景

已有原文预填、重复/回应过滤与共同显示门，但范围扩张、无依据结论和同义复述仍有反例。产品旧示例又允许完整句后补新约束，与停笔要求冲突。单纯加长提示词或过滤率不能证明用户体验改善。

静态审阅另发现 Context 选择代次不等于内容修订，部分来源先写候选再做共同门检查；因此生成内容正确也不足以保证显示、替换与接受正确。原评测中的重复运行也不能当作独立样本放大可靠性。

## 决策

1. 自动续写只完成已有依据的语义缺口；无明确缺口停笔。新的专业提示词维度需要用户依据，不能靠“相关”补入。允许必要术语以及明确请求的约束核验，不机械禁词。
2. 固定不可变输入/Context 内容修订，候选绑定实际依赖；候选先验证、再核对身份、再原子提交显示状态。保留新鲜 Tab 读取。
3. 同一有效绑定默认首个过门候选显示后固定，取消/忽略后到提案。无自动比较等待、不预设远程优于本地；迟到失败不能撤销仍有效旧候选，身份变化必须撤销。
4. 分开验证 provider 内容质量、共同门与混合展示调度；公开开发集、按家庭隔离的未见评测及管线回放各自保留。数字必须报告分母与失败，零观察错误不等于零风险。
5. 提示词 G1 先做单变量实验；模型审核先离线评估，只判不改，证明净收益及成本可接受后才考虑运行接入。

## 备选与取舍

| 备选 | 好处 | 未采用为默认方案的原因 |
| --- | --- | --- |
| 只追加提示词禁令 | 改动少，容易开始对照 | 无法解决候选事务与内容修订；规则冲突和响应式模型倾向仍可存在 |
| 每次生成后强制第二次模型审核 | 可能拦截确定性规则之外的错误 | 同模型错误相关、误杀、等待与 MLX 资源竞争；没有独立证据前不值得默认加一次调用 |
| 等本地/远程都结束再挑选，或远程到达就替换 | 有机会获得较好后到结果 | 首次等待和 Tab 目标漂移；“远程更好”未获当前证据支持 |
| 直接换大模型、换框架或全量 Runtime 重写 | 可能改善容量或组织结构 | 归因困难、侵入面大；仍不能替代语义契约、证据和状态正确性 |

## 后果与未决项

收益：范围、证据、停笔和接受身份有共同判定标准，坏候选不再借来源差异豁免；开发可用最小对比和事件回放发现回退。

代价：更保守的范围可能降低覆盖；固定首个候选可能放弃更好的后到结果；内容修订需要处理刷新抖动。共同门仍不能数学保证语义正确，必须同时测覆盖与严重错误。

以 C1 的事务/快照和回放为首个实现包，C2 再改提示词，审核与更多格式支持随后凭证据决定。数值 SLA、审核收益、候选固定的实机感受未确认；不因此扩大 M0 或宣称 M1/M2 已完成。

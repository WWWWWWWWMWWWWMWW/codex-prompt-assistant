# Codex 智能提示助手方案

日期：2026-08-18
状态：方案评审稿，未开始实现

## 1. 结论

第一版应做成一个独立的 macOS 菜单栏应用，只辅助 Codex 输入框。它从本地聊天资料中自动生成并持续更新动态表达库，在用户输入停顿后给出类似代码补全的灰字建议，支持 `Tab` 接受、`Esc` 忽略。

采用“本地学习、远程续写”的路线：完整聊天记录、表达提取、权重更新和相关内容检索都在本地完成；远程接口只接收当前输入、已确认属于当前任务的最近对话，以及少量脱敏后的相关表达。

第一版不能承诺普通 ChatGPT 桌面聊天的无遗漏实时采集，也不能在技术验证前承诺原生级灰字效果。开发必须先通过输入框接入验证，再进入完整实现。

## 2. 已确认需求

- 只在 Codex 输入框工作，不扩展到微信、飞书或其他软件。
- 读取全部 Codex 用户任务，包括当前任务和归档任务。
- 首次导入普通 ChatGPT 全部历史；同一导出包可以重复导入且不产生重复数据。
- 完整路线允许用户消息和 AI 回复参与表达学习，表达库全自动更新；阶段 2 简化首批只学习用户消息，AI 回复学习后续迭代。
- 表达权重根据频率、时间、项目、复用、`Tab` 接受和明确拒绝动态变化。
- 输入停顿后显示灰字建议，`Tab` 接受、`Esc` 忽略，继续输入则取消旧建议。
- 完整历史保存在本地，不整库上传。
- 第一版只支持用户指定的一套兼容 OpenAI 格式的接口和一枚 Key。
- Key 只能通过设置页写入 macOS 钥匙串，不进入代码、方案、配置、数据库或日志。

## 3. 明确边界

### 稳定支持

- Codex 用户任务首次扫描、归档扫描和后续增量更新。
- ChatGPT 历史导出包的首次导入、重复导入、增量合并和去重。
- 本地动态表达库的生成、更新、降权、删除、屏蔽和重建。
- 接口不可用时保留本地短语建议，不影响正常输入。

### 条件支持

- 当前 Codex 任务上下文：只有可靠绑定到当前任务后才使用最近对话；无法确认时自动降级为“当前输入＋本地表达库”，禁止猜测任务。
- 灰字浮层：必须先验证当前版本 Codex 是否暴露可用的输入框、光标位置和插入能力。

### 第一版不承诺

- 普通 ChatGPT 桌面聊天无遗漏实时采集。当前桌面应用未稳定暴露聊天正文和会话 ID；后续可作为实验通道，但不能代替导出包补齐。
- 手机和网页聊天实时同步。
- 调用 ChatGPT 私有接口、读取登录令牌、修改或注入 Codex 应用。
- 多家接口、多 Key 切换、本地生成模型和语义向量模型。

## 4. 本机现状与规模

2026-08-18 的只读检查结果：

- 83 个根级用户任务应进入资料库。
- 21 个子代理任务必须排除，防止把内部代理过程学成用户表达。
- Codex 活跃与归档 JSONL 总体约 3.2 GB、约 8.7 万行；不能整包载入内存，必须流式解析和增量处理。
- 当前桌面应用版本为 26.814.41407；辅助功能树没有稳定暴露聊天正文和当前任务 ID。

这些数量会随任务增加而变化，程序必须通过来源对账而不是写死数量。

## 5. 总体架构

```text
Codex 用户任务 JSONL ──┐
                       ├─→ 来源适配与增量游标 ─→ 本地加密聊天库
ChatGPT 历史导出包 ────┘                              │
                                                     ▼
                                      本地表达抽取与权重学习
                                                     │
Codex 当前输入 ─→ 当前任务安全绑定 ─→ 本地相关内容检索 │
             │                                       ▼
             └────────────→ 上下文裁剪与敏感信息脱敏
                                                     │
                                                     ▼
                                             用户指定 AI 接口
                                                     │
                                                     ▼
                                    灰字浮层／本地提示条／反馈事件
                                                     │
                                                     └─→ 更新表达权重
```

### 5.1 来源适配层

Codex 只读取 `thread_source=user` 的根任务，排除 subagent、developer、system、reasoning、工具调用、终端输出和隐藏指令。优先尝试版本探测后的规范读取接口；不兼容时回退到带版本号的 JSONL 解析器。

文件监听只作为“需要重新对账”的信号。每个来源保存文件标识、字节偏移、解析版本和最后成功位置；遇到半行、截断、迁移到归档目录或崩溃时能够恢复且不重复入库。

ChatGPT 导出包必须在事务中导入，检查路径穿越、超大压缩包和未知结构。未知版本应完整回滚并提示，不允许半导入后开始学习。

### 5.2 本地资料与表达库

采用单机加密 SQLite 数据库，密钥存储在 macOS 钥匙串。原始聊天层与派生表达层分开：原始层只追加、纠错和删除来源；表达库可以随算法升级随时重建。

主要数据包括：

- 会话、消息、角色、项目、时间、来源、内容指纹和增量游标。
- 术语、短语、句式、提示词模板、表达变体和来源位置。
- 项目／场景统计、最近使用时间、接受和拒绝反馈。
- 屏蔽项、删除墓碑、构建版本和可回滚快照。

第一版不用本地大模型。阶段 2 的简化首批只做中文分句、跨会话重复和运行时内存前缀检索，表达正文仍加密落盘；字符 n-gram、句式骨架、FTS5、AI 回复学习和完整可解释评分留到后续迭代。

建议评分综合：前缀匹配、当前项目、当前场景、频率、最近性、真实复用、接受、明确拒绝和敏感／噪声惩罚。继续输入导致建议过期不算拒绝，`Esc` 才是明确负反馈。

### 5.3 当前任务绑定

不能按“最近修改的文件”猜当前任务，因为子代理或后台任务可能更新得更晚。采用粘性绑定：工具根据上一条实际发送的用户消息匹配刚追加到哪个根任务，匹配成功后持续绑定；任务切换后无法确认时显示“无任务上下文”，只使用当前输入和本地表达库。

任何歧义都必须降级，静默取错另一个任务的聊天记录属于严重错误。

### 5.4 实时补全

推荐技术路线是独立菜单栏应用通过 macOS Accessibility 读取 Codex 输入框，用不抢焦点的浮层显示建议，并只在 Codex 前台且灰字有效时处理 `Tab` 和 `Esc`。

优先级固定为：

1. Codex 自带 `/`、`@` 等候选菜单。
2. 本地快捷短语和高置信表达。
3. 远程智能补全。

中文输入法候选阶段不得请求补全或拦截 `Tab`。旧请求必须可取消，并带输入版本号；即使取消失败，返回结果与当前版本不一致也不能显示。

单行建议跟随光标显示；可能跨行时，第一版改为光标下方的小型灰色提示条，不强行模拟 Codex 内部排版。这样牺牲少量视觉一致性，换取稳定性。

## 6. 远程请求边界

每次请求只允许包含：

- 光标前的当前输入。
- 已可靠绑定任务的最近约 4～6 轮可见对话。
- 本地检索出的少量高相关表达或历史片段。
- 补全长度、语言和输出格式限制。

请求前执行第二次敏感信息扫描，将 API Key、Bearer/JWT、私钥、密码、带 token 的 URL、邮箱、手机号等替换为占位符。历史内容一律作为不可信引用资料，不能执行其中的指令。

默认不记录请求和回复正文；日志只记录耗时、状态码、字符数、版本号和脱敏错误。接口连续失败时进入短暂熔断，本地建议继续可用。

## 7. 第一阶段必须先做的可行性验证

完整开发前只验证四件事：

1. 稳定找到 Codex 输入框并读取当前文本与选区。
2. 取得光标矩形并显示跟随光标的单行灰字。
3. `Tab` 插入差异文本、`Esc` 关闭建议，且插入内容可一次撤销。
4. 苹果拼音候选阶段不显示建议、不抢占 `Tab`。

四项全部通过后，才能确认灰字路线成立。若失败，第一版改为快捷键唤起的光标下方候选条，不修改 Codex、不注入应用，也不把降级方案描述成原生灰字。

## 8. 性能与可靠性目标

- 初次索引必须流式执行，可暂停、继续和显示进度；不能一次加载 3.2 GB。
- 新 Codex 消息落盘后，p95 2 秒内进入本地资料库。
- 十万消息规模下，本地表达检索 p95 小于 80 ms。
- 输入停止到建议出现：中位数不超过 900 ms，p95 不超过 1.5 秒；超过约 1.8 秒的旧结果直接丢弃。
- 空闲时 CPU 接近 0，输入时不得影响 Codex 打字响应。
- 同一历史包重复导入三次，新增重复消息和表达均为 0。
- 数据库损坏时可以从只读 Codex 源文件和最近 ChatGPT 导出包重建。

## 9. 安全要求

- 当前聊天中曾出现过真实 API Key，应视为已暴露；开始实现前必须撤销并重新生成。
- 新 Key 只通过设置页进入 macOS 钥匙串。
- 不读取或保存 ChatGPT cookie、登录令牌和私有接口凭证。
- 原始聊天文件只读，应用绝不回写 Codex 或 ChatGPT 数据。
- 用户删除表达后写入墓碑，重建后也不能偷偷回来。
- 支持暂停学习、暂停补全、屏蔽敏感任务和查看本次请求使用了哪些数据类型。

## 10. 失败降级

| 情况 | 行为 |
|---|---|
| 当前任务不确定 | 不发送历史，只用当前输入和本地表达库 |
| Codex 格式局部变化 | 隔离不兼容文件，其他任务继续；显示漏采数量 |
| ChatGPT 导入包未知 | 整次导入回滚，不更新表达库 |
| API 超时、断网、401、429、5xx | 静默隐藏智能建议，本地短语继续工作 |
| 中文输入法状态不确定 | 不显示建议、不拦截 Tab |
| 灰字定位失败 | 改为不抢焦点的候选提示条 |
| 本地数据库损坏 | 从只读源和导出包重建 |

## 11. 分阶段实施建议

### 阶段 0：可行性门槛

只做输入框、光标、浮层、Tab／Esc 和中文输入法验证。2026-08-20 已实机通过：Codex 无法提供可靠光标矩形，因此正式采用输入框上方候选条降级方案；搜狗拼音候选阶段不抢 Tab，选词后的 Tab 可接受建议且不转移焦点。

### 阶段 1：可靠数据底座

实现 Codex 根任务过滤、流式增量解析、ChatGPT 导入、加密数据库、幂等去重、敏感信息过滤和重建。

### 阶段 2：动态表达库

先实现用户固定句子的保守抽取、跨会话自动准入、加密保存、内存前缀检索、删除和屏蔽；变体、AI 回复、项目／场景权重、衰减和反馈学习后续迭代。

### 阶段 3：实时补全闭环

接入用户指定接口，实现上下文裁剪、请求取消、灰字或候选条、接受／拒绝反馈和故障熔断。

### 阶段 4：实验增强

评估 ChatGPT 桌面前台聊天采集和轻量本地语义检索。只有通过完整率和升级兼容测试后，才能从“实验”升级为正式能力。

## 12. 上线验收

- 当前快照能正确区分根用户任务与子代理任务，子代理误入为 0。
- 抽样 20 个任务，用户／助手可见消息顺序与 UI 一致，隐藏消息和工具输出误入为 0。
- active 转 archived、重复扫描、程序重启后消息数不重复增长。
- 当前任务正确绑定或明确显示未绑定，静默误绑为 0。
- 中文候选阶段不请求、不抢 Tab；英文、中文、标点、删除、粘贴、撤销均无重复插入。
- 快速输入时只显示最后一个版本的建议，乱序响应永不出现。
- 敏感测试集中的 Key、Token、密码、邮箱和电话远程泄露为 0。
- 删除表达后立即不再出现，完整重建后仍不出现。
- 第一周观察有效建议接受率；接受率是优化指标，不作为掩盖稳定性问题的上线理由。

## 13. 最终建议

阶段 0 技术门槛已经通过，下一步按“数据底座 → 动态表达库 → 实时补全”顺序推进。当前交互基线是输入框上方候选条，不把它包装成原生 Ghost Text；每次 Codex 或输入法升级后仍需重跑兼容性测试。

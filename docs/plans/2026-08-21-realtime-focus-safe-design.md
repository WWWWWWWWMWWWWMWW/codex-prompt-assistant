# 实时响应与无焦点打扰设计

日期：2026-08-21

## 目标

把本地建议的触发等待压到 200ms 内，把远程建议的典型总等待降到约 1～1.3 秒；候选条显示、隐藏和同一草稿重新聚焦都不得激活助手、抢走 Codex 焦点或反复触发 Dock 图标。

## 方案选择

只缩短原来的 650ms 防抖，无法解决 5.6 Sol 本身约 2～3 秒的响应；直接做流式增量刷新会引入 SSE 解析、部分后缀一致性和频繁重绘，首版风险偏高。当前采用中间方案：AX 探测从 250ms 调整为 100ms，空闲防抖改为 180ms，中文输入法候选仍可见时每 120ms 复查；远程内联补全改用真实接口连续实测约 0.87～1.05 秒的 `4.1-nano`。本地表达命中仍优先，不会产生网络等待。

## 焦点与显示

候选面板继续使用不可成为 Key/Main Window 的 `NSPanel`，关闭动画、鼠标事件和 `orderFrontRegardless`，仅通过非激活的窗口排序显示。Codex 暂时失去前台状态时隐藏并取消在途请求，但保留已观察草稿；返回同一草稿不再重新发请求或重复弹窗，只有实际内容变化才重新触发。应用未配置时不再启动即自动弹设置框，所有会激活助手的 NSAlert 只保留在用户主动点击菜单的路径中。

## 钥匙串与启动

现场进程采样确认 Dock 闪烁并非候选面板本身，而是临时签名重编译后读取历史 Keychain 条目触发系统授权。启动菜单状态改为只读非秘密配置标记；历史派生库改用 `master-key-v3.bin`（目录和文件均为当前用户专属权限）与 `history-v3.sqlite3` 自动重扫，旧库和旧 Keychain 条目均保留，不做破坏性覆盖。远程 API Key 仍使用新版 account 和固定助手路径 ACL，仅在真正远程请求时读取。

## 验证

- 纯函数测试约束 100ms 探测、180ms 防抖、120ms IME 复查和重新聚焦保留草稿。
- AppKit 测试显示候选条前后核对前台进程和助手激活状态不变。
- 真实接口以合成中文前缀测试快速模型延迟，只记录模型、状态、耗时和字符数。
- 全量回归、逐文件 Clang Analyzer、签名和凭证扫描通过后再启动最新应用现场观察。
- 启动后采样所有线程确认没有 `SecItemCopyMatching` 阻塞，并用 LaunchServices 验证应用类型保持 `UIElement`。

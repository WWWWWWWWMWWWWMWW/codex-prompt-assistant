# 助手启动配置准备实施计划

**目标：**为安装维护者生成绑定目标用户、已核对助手包和模型保护参数的启动配置，减少手工改 plist 的步骤；不加载服务、不复制到安装位置。

**实现：**使用 Python 标准库，复用 `prepare_update.py` 的严格验签、包树摘要和可执行文件散列。生成直接执行助手的参数数组，不经过 shell；固定已有 label、`--preserve-resident-model`、启动与异常重试策略。仅在仓库 `.build/helper-agent-preparations/` 新建排他目录，先验证包、再写配置与记录。

## 依据与选择

已确认：Makefile 旧安装入口先覆盖包/配置，再验签；模板经 shell 执行且缺少当前加载配置的模型保护参数。当前稳定运行使用独立 guarded plist，不能将旧入口当成安全安装方式。

建议采用独立准备工具：可以先核对结果，不碰当前运行；直接改模板并安装会同时改变模型生命周期；立即制作一键安装器则仍缺签名渠道、目标用户供给和失败回退依据。后两种不纳入本轮。

## 工作步骤

1. 在 `Tests/ReleasePreparationTests/test_helper_agent.py` 建立行为用例：不同用户名与特殊字符按字面处理、固定服务参数、错误身份/散列/保护能力拒绝、现有输出保留、写入中断不形成完成记录。先运行并记录失败。
2. 新增 `Tools/Release/helper_agent.py`。包必须在目标用户约定的安装位置；严格验证签名、元数据、可执行权限与显式 SHA256，拒绝链接/特殊文件。dirty 包只允许准备本机检查材料，记录 dirty，不放行发布。准备结果包含 plist 和 manifest，读取/写入后再核对包摘要。
3. 运行 `make release-preparation-test` 与关联模型保护测试。针对当前安装包实际生成准备材料，比较生成配置与正在加载的 guarded plist；当前磁盘原 LaunchAgent 保持。
4. 核对前后进程、已安装包、偏好摘要和服务配置，更新 `docs/release.md`、`docs/status.md` 和验收记录。本轮工具不进入 app bundle，因此不重建或重载助手，不冒充普通用户安装/真实回退通过。

## 验收与后续依赖

准备材料可审查、无 shell 插值、无凭据、无服务调用；错误时不覆盖旧配置或安装包。C22 仅完成配置准备子项，C23 通用失败回退仍未验证。需先锁定来源供给与签名/安装身份，再整合普通用户安装入口和干净用户验收；现有用户配置、模型和 Codex 连续性保持。

本轮不提交、推送、分发或恢复自动化，按已授权范围在原工作区实施。

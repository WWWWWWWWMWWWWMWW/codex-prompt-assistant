# 用户明确范围的字面承接

用户要求安装后继续上一轮提出的范围/否定约束优化。已先安装 .3。此工作包保持当前运行版本，先验证再构建下一候选，不二次重载或修改模型/开关。

## 选择与范围

现有模型提示词已含 draft_focus 的限定范围与禁止操作；此前提示词及上下文裁剪没有稳定通过原意保持，因此不再叠加通用提示。通用语义审核也没有可靠收益，暂不接入。选择复用明确选项路径的局部字面承接：当前草稿为已有七种固定“如何”句首，最后一条消息为用户完整、明确、有限动作要求时，逐字接出该要求的动作与否定限制。

支持完整用户文本：`只/仅 + 有限动作`，可带一条 `，不/不要 + 有限动作`，末尾可有一个句号。支持完整覆盖前缀 `取消之前/原来（的）方案，改为`，只取其后用户明确写出的替代要求，不从旧历史推理对象。例如“取消之前方案，改为只改颜色，不动布局。”→“只改颜色，不动布局。”。任何其他前缀、条件、引号、附加句子、多项/旧选项指代、缺对象或新助手消息均不做此提取。180 字上限，汉字动作与有限动词；不提供如何执行的答案。

与 .3 明确选项函数分开，标记 explicit_user_scope，模型请求数为零，不清空服务故障冷却或失败计数。调用仍在配置、输入与用户上下文门后，仍过共同文本门和原发布/接受保护。模型路径保留，不宣称此路径之外的范围错误已消除。当前草稿含具体对象/修订时优先尊重草稿，本路径不匹配。

## 验证设计

事前固定 8 条开发场景（6 条用户范围/替换，2 条已有选项控制），现版两路各两轮；候选相同文本在生产客户端本地配置两轮禁网验证，两个 API 路径另用 HTTP 替身覆盖。比较拼接全文，允许等义的基线好结果，不用字面相等给模型语义打分；系统失败与停笔分开。候选应全部精确承接，无范围扩展、否定遗漏或旧方案残留，旧选项控制不退步。

另提前冻结 6 条留出样本，开发集通过后再运行；它们同属这些语法家庭，由同一代理编写，不是独立盲测。增加协议拒绝用例和客户端配置/取消/冷却保护测试；旧 69 条格式回放沿用原期望。留出与固定回归出现关键偏移则不采用。报告请求数、有效覆盖、原始/最终文本、拒绝和决策延迟；不把离线客户端时间当实机提示时间。通用语义发布仍需原评测规范中的独立家庭验收。

## 实现与验证边界补充

最终实现是有限语法和标记表，不能识别全部隐式条件、指代或同义冲突，也会保守拒绝“不透明度”等含标记的合法对象。命中时保留整个动作及一条排除原文，不凭解析结果证明用户要求逻辑无矛盾。非命中沿用既有门禁/生成，可能停笔，也可能继续请求模型。

最终开发/留出结果与编排失败记录见对应验收；留出协议启动早于异步开发结果完整检查，因此不称严格盲测流程，留出客户端在开发检查通过后运行；未看结果后修改实现或金标。

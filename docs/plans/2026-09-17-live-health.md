# 按需健康回执与停止确认

目标：补齐更新流程中实时健康和停止确认的证据。沿用 Code 与前述设计约束，本轮直接实施局部、可逆方案，不新增设置或扩大分发。

采用当前用户内按 PID 命名的 CFMessagePort。随机 nonce 请求由主运行循环处理，响应仅含进程/本次实例、构建身份、当前事件监听启用、辅助功能许可与模型保护布尔状态。每次有界等待，拒绝旧回执、错误协议和目标 PID；不读取输入、生成候选或发送外部请求。进程映射/包身份与回执前后核对，健康仅表示该时刻主线程响应和监听/权限状态，不表示生成质量或插入成功。

相较周期心跳文件，本方案没有持续磁盘写入或旧文件失效问题；相较直接读取启动日志，能检验当次响应。此 IPC 仅为同用户维护诊断，不是对同用户恶意进程的身份认证机制。

步骤：新增 responder/客户端及隔离测试；app 启动注册、退出注销，独立 --health-probe 分支在 NSApplication 初始化前返回；只读检查工具在明确协议标记、验签/映射成功后调用。停止检查只认固定 label 的明确不存在错误以及原 PID 的 ESRCH，权限错误/未知状态不猜测通过。

完成应用和发布相关测试后构建验签，沿用已审查的有限本机安装器备份并更新助手；安装时核对停止确认，安装后请求实时回执。Codex/模型、偏好及服务配置保持。真实通用失败回退、新用户授权和实体 Tab/Esc 保留独立门槛。

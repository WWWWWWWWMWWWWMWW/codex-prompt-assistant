# 生成、候选过滤与上下文边界工作包

## 已确认

用户确认显示/Tab 项可以收尾，要求继续生成质量、过滤与候选选择、上下文边界三项。显示/Tab 按用户实机确认记录，不冒充自动化回读证据。保留当前双开/Terra、表达库暂停，不重启模型或 Codex。本轮只改源码、做合成验证和构建，不安装或提交。

## 方案与验收

生成层优先做材料来源对照。已有多轮通用提示词追加、格式切换、二次审核未通过，不重复原方案；新实验比较完整历史与最近一条用户材料，检验助手解释污染、否定、更正、范围、简短确认及指代。两路分别要求关键含义不变、严格可用数量不低于基线、确认/指代场景不退化。未达门槛不改生产上下文选择，也不把远程天然视为正确。

过滤层限定于因果句和疑问词的位置：后出现的“如何/是否”不能授权此前已陈述的原因；草稿末尾已有“是否/是不是/会不会/能否”只作用于直接续写的第一分句，不能跨越标点。共同最终门执行同一规则，保留正常陈述和明确提问。该规则只检查句法作用范围，不推断原因是否真实，也不改写候选文字。

上下文层复用当前 ID 事务和 generation。新增字段、进程、上下文模式、选中节点缺失与失去前台的最后快照用例；最后绑定时再次检查 snapshot 前台和进程。保持普通输入复用 UUID、首次/导航/Tab 核验、身份缺失只使用草稿的既有行为。以合成 A→B→A→解析失败的 64 次回放检查两路请求和迟到候选，不制造真实用户任务。

候选选择保留第一条合格显示固定、不被迟到结果替换。本轮对照未建立可靠的通用来源质量排名，因此不引入远程优先或任意评分。过滤新拒绝的候选不会占据显示位置，应通过生命周期测试确认后续合法候选可继续显示。

## 交付证据

先复现新断言失败，再执行 remote-completion-test、make test 与扩展后的候选生命周期回归；固定 240 条输出做旧/新协议回放，单列新增拒绝、恢复放行及既有样本变化。构建、签名与 Git/dirty 身份独立记录。实机切换压力、模型泛化质量和新包运行行为不以离线结果代替。

# 2026-09-08 上下文读取修复与验证

## 已确认的原因

1. Codex 浮动聊天窗口的 WebArea URL 为 `app://-/index.html?initialRoute=%2Favatar-overlay`。它没有侧边栏，旧实现只能找侧边栏选中项，无法识别任务。
2. 当前任务在 session_index 中有同名的已归档副本和未归档记录。旧实现遇到两个同名 ID 直接返回空，读取探针复现 `count=0`。
3. 旧上下文仅取最近两条消息的前 600 字符，没有排除 assistant 的中间过程。现场新版记录使用 `phase=commentary`，不能只检查 `channel`。
4. 任意字节位置截取日志后直接 UTF-8 解码，可能因起始位置落在中文字符中间而丢失整个结果。

## 修改

- 以当前输入框所属 AXWindow 为读取边界，切换窗口时清除旧识别缓存；不再从所有窗口里挑第一个选中任务。
- 只有已验证的本机 avatar-overlay 页面可以使用 `关闭“任务名”` 按钮作为任务身份。普通页面、泛化关闭按钮不具备这个资格；发现多个浮动任务标签时不猜选。
- 同名映射中存在唯一未归档记录时使用该记录；多个未归档同名任务继续返回空。单一归档映射保持兼容。
- 最多保留最近 6 条用户消息和 2 条最终 assistant 回复，按原时间顺序送入模型。兼容 `channel=final`、`phase=final_answer` 及旧记录，排除分析、进度说明和单独的环境信息消息。
- 每条用户消息最多 400 字符，每条最终回复最多 300 字符，总量不超过 3000 字符；长消息保留开头和结尾，中间明确标记省略。字符边界不拆分组合字符。
- 有限读取当前任务日志末尾 8 MiB；先按字节跳过不完整首行，再进行 UTF-8 解码。非常长的任务仍可能只找到少于 6 条用户消息，不承诺读取全历史。
- 本地请求等待首批数据的超时调整为 10 秒，总请求上限 12 秒；远程维持 5/6 秒。输入变化的取消和过期候选隔离保持生效。日志新增 `contextChars`，不记录历史正文。

## 验证结果

- `make test`、`make -B app`、`make remote-completion-test`、`git diff --check` 均退出 0。
- 构建和安装产物严格 codesign 验证通过，两份可执行文件逐字节一致。
- 回归测试覆盖归档同名、多个活动重名、会话切换和异步旧结果隔离、消息角色配额、两种最终回复标记格式、中间过程过滤、首尾约束保留、UTF-8 截断、浮窗 URL 与标题识别。
- 原生只读探针验证浮窗及主窗口都能识别当前任务并读取非空历史。
- 最终助手在 Codex 浮窗实测：`contextCount=6 contextChars=681 inputLength=21`；请求耗时 2441 ms，输入观察至完成 2898 ms，显示 22 字符候选。测试草稿完整清空，没有发送消息。
- TextEdit 独立合成草稿实测：提示显示、最终版本 Tab 插入 26 字符、恢复原测试文本成功（中间版本插入 28 字符也通过）。
- 3000 字符合成历史上限测试：新的历史前缀首次处理 7013 ms 成功返回 14 字符；缓存前缀样例 641 ms 返回。此前 6000/3000 字符在旧 5 秒超时下失败，因此未保留 6000 字符方案。耗时不是所有输入的性能保证。

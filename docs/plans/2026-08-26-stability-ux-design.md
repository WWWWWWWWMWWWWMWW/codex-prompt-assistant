# Codex 提示助手稳定性与轻量交互设计

## 目标与边界

在不退出、重启、激活或改变 Codex 启动方式的前提下，将提示助手收敛为一个低干扰、可预期、可随时停止的辅助层。候选只在 Codex 前台、输入目标可确认、草稿稳定且当前任务代次一致时显示。无法确认输入目标、中文候选状态、光标位置或任务边界时保持静默，不以“更容易出提示”为由猜测。日志仅记录状态、计数、字符数、耗时和坐标，不记录输入正文、模型正文或密钥。

## 状态机与关闭语义

应用状态为 `running` / `paused` / `terminating`。`running` 保留现有 AX 优先、窗口锚点降级和键盘影子路径。`paused` 立即隐藏候选，取消本地／远程请求、候选定时器、焦点恢复和轮询，停止全局键盘事件点并暂停历史扫描；本地模型保持预热，以便快速恢复。`terminating` 在 `paused` 清理之上停止上下文观察、移除 workspace 通知、刷新诊断队列，并停止由提示助手拥有的本地 Qwen 服务。任何关闭路径都不得向 Codex 进程发送退出、激活或启动请求。

## 候选生命周期与误触发

候选显示时固化其输入签名、输入草稿、任务代次和插入文本。Esc 必须基于“已显示候选”记录取消，不再于 AX 瞬时失效时重新抓快照；只有输入真正改变才允许新候选。Tab 接受后进入短冷却，程序插入和紧随其后的微小输入不得立即再发起模型请求。快速编辑使用分层节奏：本地历史命中可快速显示，本地模型在草稿稳定后触发，远程模型再晚一层；删除、选区、中文组词和持续输入期间不启动高成本请求。任务代次变更继续取消并丢弃所有旧任务回包。

## 轻量 UI

候选条继续使用不激活、忽略鼠标事件的 `NSPanel`，不生成 Dock 图标或主窗口。视觉上使用稳定宽度的单行轻量条：左侧为最多一行的续写，右侧为低对比度 `Tab 接受` / `Esc 取消` 快捷键提示。流式更新只替换文本，不随 token 持续改变窗口宽度或位置。首次出现可用 80–120ms 透明度过渡，文本更新不做移动或尺寸动画。暂停时菜单栏图标和文案明确变为“已暂停”，不使用弹窗打断用户。

## 验收原则

自动化测试验证状态机、取消／接受冷却、定时器和事件点清理、候选稳定尺寸、日志轮转和任务代次。真实 UI 验收分别记录中文、英文、Tab、Esc、任务切换、切应用、暂停／恢复和完全退出。CPU、RSS 和日志增长使用有时长的多次采样，不用单个瞬时值宣称稳定。实际检查前均标记为“未验证”。

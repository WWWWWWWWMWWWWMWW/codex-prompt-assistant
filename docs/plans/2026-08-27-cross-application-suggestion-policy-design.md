# 跨应用智能提示策略设计

## 目标与原则

将当前只服务 Codex 的提示助手扩展到 WorkBuddy、飞书、微信和浏览器正文表单，同时保持低打扰、低误触和可解释。默认采用“分层白名单 + 推荐预设 + 本地优先”：已适配应用只在明确的普通编辑场景按预设工作，陌生应用和语义不足的控件保持静默。

决策必须发生在读取输入正文、维护键盘影子缓冲、调用本地或远程模型之前。密码、验证码、登录、支付和安全文本框是不可被用户例外绕过的硬保护。搜索框是可配置的软保护：默认禁用，只允许用户对精确应用或站点开启例外。

## 圆桌裁决

- 产品与 UX 要求推荐预设开箱可用，并显示“为什么提示／不提示”。
- 隐私与安全要求硬保护不可覆盖，非 Codex 应用首期默认只使用当前草稿和本地模型。
- 架构与成本要求用通用规则引擎和应用适配器取代散落在主流程中的 bundle ID 特判，陌生应用不弹首次询问窗口。

综合结论是：不选“全局自动开启”，因为尾部误判和隐私事故的长期成本最高；不选“每个应用首次弹窗”，因为会打断输入并引入额外状态管理。陌生应用只在菜单栏被动显示“当前应用未启用”，用户可一键启用。

## 架构

```text
前台应用／焦点变化
  -> InputContextCollector
     bundle ID、PID、浏览器 host、AX role/subrole、安全标志、场景置信度
  -> SensitiveGuard
     密码／验证码／登录／支付／语义不足直接拒绝
  -> SuggestionPolicyEngine
     全局暂停 > 硬保护 > 显式禁用 > 显式例外 > 推荐预设 > 默认关闭
  -> AppAdapter
     Codex / WorkBuddy / Lark / WeChat / Browser
  -> SuggestionPipeline
     关闭 / 仅本地 / 本地+远程
```

规则结果不只返回布尔值，而是包含生成模式、上下文模式和可解释原因。非 Codex 首期固定为“当前草稿 + 仅本地”；远程发送和历史学习必须分别授权。Codex 任务标题、会话映射和深层 AX 扫描保留在 Codex adapter，不允许其他应用复用。

## 预设与设置

| 应用 | 推荐场景 | 首期生成 | 默认关闭 |
| --- | --- | --- | --- |
| Codex | 任务提示编辑器 | 本地 + 已配置远程 | 搜索、设置和其他控件 |
| WorkBuddy | 主提示词编辑器 | 仅本地 | 搜索、登录、语义不足控件 |
| 飞书 | 文档、评论、明确长文本编辑 | 仅本地 | 聊天、搜索、登录 |
| 微信 | 无自动开启预设 | 用户启用后仅本地 | 全部场景 |
| 浏览器 | 用户允许站点的正文编辑器／多行表单 | 仅本地 | 未知站点、无痕、搜索、登录、支付 |

普通设置每个应用只显示“推荐／普通输入均启用／关闭”三态。搜索框例外、站点名单和场景覆盖放在折叠的高级设置。“普通输入均启用”仍不能绕过硬保护。

## 状态与性能

菜单栏使用“应用 · 场景 · 状态”格式，例如“飞书 · 文档编辑 · 已启用”和“Chrome · 搜索框 · 已保护”。一键动作包括暂停 30 分钟、关闭当前应用／站点、为当前应用／站点启用。

从“所有应用每 100ms 深扫 AX”改为事件优先：应用激活、焦点、窗口或站点变化时重新决策，只有在已允许的输入框中才保持短周期输入监测。规则结果按 PID、窗口／字段身份和规则版本缓存；切应用立即失效。未启用应用不扫描深层 AX 树、不维护草稿、不启动模型。

## 安全、日志与验收

硬保护场景必须实现“零正文读取、零模型请求、零候选”。日志仅允许原因码、应用类别、AX 角色、计数、耗时和错误码；不记录输入正文、模型正文、字段标签、窗口标题、聊天对象、完整 URL、API Key 或应用内深链。站点 host 只保存在本地设置，不写诊断日志。

实际验收矩阵要分别覆盖 Codex、WorkBuddy、飞书、微信、Safari 和 Chrome 的普通输入、搜索、登录、验证码、切应用、Tab/Esc 以及暂停／恢复。只有真实检查后才标注“已验证”，其余必须明确保留为“未验证”。

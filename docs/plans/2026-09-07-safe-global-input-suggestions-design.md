# 安全全局输入提示设计

## 目标

将提示助手从 Codex 专用扩展为跨应用输入助手，同时保持默认安全、可解释、可随时关闭。普通文本输入框默认提供本地提示；高风险应用或场景必须由用户明确开启；敏感输入始终禁止读取和提示。

## 已确认方案

采用“安全全局模式”：

- 普通编辑器、文档、聊天输入框默认启用。
- 非 Codex 应用只读取当前输入框，不读取会话历史、页面正文或剪贴板。
- 非 Codex 默认只使用本地补全；远程补全继续要求按应用显式授权。
- 浏览器按精确站点授权，未知站点默认关闭。
- 搜索框、终端和代码编辑器默认关闭，可从状态栏菜单手动启用普通输入。
- 密码、验证码、登录、支付、安全文本框及系统授权场景永久关闭，手动开启也不能覆盖。

## 策略分层

### 1. 永久拦截

策略判定先于输入正文读取。命中以下任一条件时，不读取正文、不请求模型、不显示提示：

- `AXSecureTextField` 或安全输入标记；
- 密码、一次性验证码、登录、支付语义；
- 系统登录、安全代理和授权类应用；
- 无法确认输入控件身份或语义置信度不足。

### 2. 默认手动开启

以下类型在推荐模式下不主动读取输入元数据，用户明确开启后仍受永久拦截约束：

- 浏览器：只对当前精确主机名生效；
- 终端：按应用开启；
- 代码编辑器与 IDE：按应用开启；
- 搜索框：需要额外开启搜索输入例外。

### 3. 默认本地启用

其他普通 macOS 应用在推荐模式下可以检查输入元数据；只有确认是普通文本输入控件后，才读取当前输入框内容并生成本地提示。输入焦点或控件身份变化时，旧提示立即失效。

## 用户界面

状态栏菜单增加“当前应用”策略区：

- 显示当前应用名称和当前策略结果；
- 提供“推荐”“启用普通输入”“关闭”三种模式；
- 浏览器在能识别当前站点时显示并配置精确站点；
- 提供搜索框例外开关，但不影响永久拦截项；
- 修改后立即重新检查当前输入框，无需重启助手或 Codex。

## 运行与隐私边界

- 先读取角色、子角色、标签、占位文本等元数据，再做策略判断；只有允许时才读取 `AXValue`。
- 浏览器 URL 仅在内存中归一化为主机名，设置只保存主机名，不记录完整 URL。
- 日志只记录结果类别和耗时，不记录 bundle、站点、输入正文或 URL。
- Codex 保留现有会话上下文能力；跨应用不继承该能力。

## 验收标准

- TextEdit、备忘录等普通输入框在推荐模式下可以出现本地提示。
- Lark、微信等普通聊天输入框在推荐模式下可以出现本地提示，但不会发送消息。
- Chrome、Safari、终端、VS Code 等默认无提示，手动开启后普通输入可用。
- 浏览器只对明确开启的当前站点生效，不扩大到整个浏览器。
- 密码、验证码、登录、支付输入在任何模式下均无正文读取和提示。
- 菜单切换无需重启，测试、构建、签名通过；安装后的真实应用至少完成一次无发送型验证。

## 非目标

- 本阶段不自动读取第三方应用的会话记录、文档全文或网页正文。
- 不自动为非 Codex 应用启用远程补全。
- 不承诺所有自绘输入控件都能被 macOS Accessibility API 识别；无法识别时保持静默。

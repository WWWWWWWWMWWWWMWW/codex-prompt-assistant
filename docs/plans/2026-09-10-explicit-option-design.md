# 明确选项的字面续写

当前用户要求继续优化“第二项”引用与范围扩展。前几轮材料裁剪无法稳定改善生成，改用局部确定性路径：仅在泛化的“我希望先了解如何”等七种固定句首、最新相邻消息为 assistant 编号动作列表 + user 单项选择时，直接返回被选动作加句号。句子仍是用户的提问，不提供如何执行的答案，不执行选项。

支持 2–3 项中文“第一项是…”或数字“1. …”列表，逐项连续、没有重复动作；动作限中文、明确动词开头及有限长度。选择必须整句匹配“只做/只选/只选择/只采用（你提到/说的）第N项”，不得有条件、多选、否定、附加要求。列表必须完整匹配，条件、引号、代码、截断标记、缺项、不支持的格式均不提取。若当前草稿已有具体对象或限制，不覆盖其意图。没有足够确定性时沿用原路径，不宣称所有失败用例都会停笔。

此路径使用原消息片段，不总结、不补充字段或操作，也不把助手陈述升级成事实。返回后仍走当前最终过滤、长度门、任务代次/签名及接受时焦点与 UUID 校验。仅减少已精确命中的调用，不改变本地/远程开关；明确标记 explicit_option 和 HTTP status 0，不能记成模型成功响应。

协议和客户端新增断言先复现失败，再完成实现。验证所有序号、中文/数字格式、不同动作和固定句首；阴性验证多选、条件、旧列表、修订选择、真实语义回答、含糊/缺失/截断选项。检查两个 provider 都无 HTTP、选择修订不复用旧结果、共同门与 Tab/失效保护保持。另以事前固定的新动作和格式执行禁网合成端到端验证，区别字面生成与模型结果。

仅开发、验证、构建；通过后交付候选，不自动安装，不重启服务，不写模型配置，不提交或推送。该窄格式功能不代表通用语义指代、所有列表形式或范围理解已经解决。

# 产品契约

面向使用者、维护者和验收者。本文收敛用户已明确的要求，不表示当前模型或所有输入路径已经全部满足。当前实现和缺口分别见 [架构](architecture.md) 与 [状态](status.md)；应用支持只在状态页维护。

## 用途与边界

帮助用户在 macOS 输入框中，把正在写给 AI 的需求续写为可直接使用的指令。主交互是输入 → 候选 → Tab 插入 / Esc 取消 → 用户自行发送。技术上以本地处理为主，保留可选远程；本机开关不是新安装默认值。

“专业提示词”要求指令明确、语境完整、约束可核查。自动续写固定站在作者一侧，先接顺原文，再按需要深化同一个请求的核查、比较或证据要求；不再限定于补完最短分句。明确的只/仅/不要限制优先，不借深化改变任务、输出字段或优先级。不要求每条后缀重新写一套完整模板。不是客服回复、自动答题、自动发送、跨应用完整聊天记忆或任意软件都可插入的产品。核心判断、候选生命周期及提示词实验见[核心体验设计](plans/2026-09-08-core-completion-design.md)，其中 C1 已完成源码与离线回放，整体语义及实机仍未验收。

## 已确认的输出与交互要求

| ID | 验收契约 | 判定方式 |
| --- | --- | --- |
| P-01 | 只返回光标后可插入的新文本，先接顺原句；保持作者的人称、语气、否定条件和任务范围 | 把原文与后缀拼接后审读，不仅单看候选 |
| P-02 | 不回答、执行或解释草稿；不写“我可以”“建议你”等回应式表达，不新增主观评价或判断，不加标题、说明、致歉 | 检查表达所扮演的角色；引用这些词作为禁止示例不应机械拒绝 |
| P-03 | 不复述原文或已接收内容的完整命题，不猜事实、原因、负责人、期限、数字或结论 | 对照原文和实际选入的上下文；仅已提出且缺值的具体项保留待确认。必要术语、指代及用户明确要求的核验关系不按重复关键词机械拒绝 |
| P-04 | 给出完整且相关的续写，不为凑长度扩大任务；无合理新内容允许无候选 | 同时报告相关性、候选覆盖率与拒绝率，不能靠全部拒绝声称质量提升 |
| P-05 | 空输入/占位符不自动出候选；保护或策略拒绝时不提供建议 | 空输入、默认拒绝、关闭、敏感场景分别验收；无候选不自动证明没有读取 |
| P-06 | 策略允许后才读取正文；敏感场景、永久保护应用不能被启用规则绕过 | 元数据/正文分离测试、明确的读取计数或诊断证据；Codex 当前差距见架构 |
| P-07 | Tab 只接受当前有效候选，Esc 取消；输入、焦点、任务或规则变化后旧候选不可插入 | 事件序列与真实输入读回；同长度替换也必须测，不能只比较长度 |
| P-08 | 接受后可继续检查下一条；关闭应撤销候选，重新启用不要求重启 | 同一进程内操作；允许最终没有合格候选，不保证每次都有下一句 |
| P-09 | 用户决定发送；测试和日常候选都不得自动提交输入 | 无发送夹具、未触发发送控件、测试草稿归属与恢复记录 |

输出应形成可直接插入的连贯片段，可以是几个相连的分句或句子；简单缺词仍只补词，不凑字数。长度随语义自然变化。完整句没有明确衔接需求时应停笔；信息不足、引用/链接/占位符等结构内部可不补全。兼容已有段落、列表和代码围栏边界，不新增格式包装。源码的资源上限、短片段规则不等同于产品长度目标，也不意味着输入满一定字数就会出现提示。当前验证及保守限制见 [续写质量记录](validation/2026-09-08-continuation-quality.md)。

## 固定语义验收示意

下面均为合成示例，不是已运行的评测集，也不是唯一标准答案。候选须结合实际上下文判断；不可靠时允许无候选。

| 场景与原文 | 可接受方向 | 不可接受方向 |
| --- | --- | --- |
| 空白或只有占位符 | 无候选 | `，内容将按原意整理……` |
| `为什么这里会重复？请先核对是否命中了`（没有具体核查对象） | 无候选，不猜对象 | `相同请求缓存。` 或回答已确认的故障原因 |
| `请把正文翻译成英文，只输出` | `译文。`，接完明确输出关系 | 新增术语表、解释翻译策略，或为凑字数扩写 |
| `请整理这次复盘的`（没有更多上下文） | 无候选；不能仅凭“复盘”指定产物 | 自行增加核查步骤、负责人或承诺帮忙 |
| `输出核查清单，未确认项单列。` | 无候选，已完整 | 再次续写同一条限制，或增加新的验收维度 |
| `只检查飞书，不扩展到WPS。` | 无候选，已完整 | 增加 WPS、复现步骤、验收结果等未请求任务 |
| `只改颜色，不动布局。请核对是否遵守上述限制，重点确认` | `布局是否保持原样。`，完成明确要求的核查关系 | 断言布局已经正确；加入性能核查 |
| `继续支持吧，`（没有更多上下文） | 无候选，不添加默认待确认清单 | 擅自指定应用、负责人、交付日期，或承诺持续跟进 |

2026-09-17：不再用问句关键词或句末标点作为请求前硬停笔条件，接受候选后的完整句和继续手动输入的第二句均可请求同主题作者续写。模型仍可因语义已充分而返回空；明确限制、禁止回答、编造与重复检查保留。该行为已完成离线调度和输出过滤回归，新包的真实联网/实体 Tab 尚未验收。2026-09-10 用户确认的同主题深化方向保持，不沿用“所有续写必须最短”的解释。公开开发种子、歧义边界、验收分母和独立评审要求统一见[评测规范](evaluation/core-continuation-v1.md)，不把示例数当作已通过评测数。

## 信息来源与未提示体验

“普通应用仅当前输入”限定于实时采集与模型对话上下文；现有历史表达候选仍可能从跨任务的本地表达库匹配。不能把该候选当作当前任务事实，也不能把本地模式等同于没有历史数据处理。现有不同候选来源的共同质量契约仍待完善。

验收与诊断区分保护拒绝、输入不足、正在生成、质量拒绝、上下文不可用和模型失败。当前界面没有完整统一原因说明，属于后续体验工作；这些原因不应成为插入正文，也不以默认套话掩盖失败。

## 待确认的产品决策

向他人分发还是仅本机使用、对外名称、模型分发方式、可接受的首次等待时间尚未确定。当前不因此增加收费、云同步、下载或发布工作；也不阻碍整理现有工程基础。

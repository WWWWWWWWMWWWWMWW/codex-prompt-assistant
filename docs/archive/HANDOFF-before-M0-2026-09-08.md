## 2026-08-21 14:12 性能与诊断优化

### 当前目标

减少本地输入链路的额外等待和主线程写盘，同时让远程请求的阶段、错误和缓存行为可追踪。

### 已完成

- 普通输入防抖从 180ms 调整为 120ms，中文输入法复查从 120ms 调整为 80ms。
- 远程客户端增加最多 8 条、15 秒 TTL 的进程内结果缓存；同一草稿再次出现时异步返回缓存结果，不重复请求网络。
- 诊断写入改为串行后台队列，主线程不再同步打开、追加和关闭日志文件；退出时显式 flush。
- 远程 API Key 首次读取改为独立后台串行队列；现场曾观察到主线程 Keychain 读取约 10 秒，本轮不再让它阻塞输入监听。读取成功后只在进程内短暂复用，设置变更会清空缓存。
- 后台 Keychain 准备增加 2.5 秒超时和过期结果丢弃；本次现场首次读取约 5 秒后成功，因焦点已变化而丢弃请求，但已缓存 Key，后续输入不再重复等待。
- 远程结果增加请求 ID、阶段、模型、缓存命中、错误域／码／安全错误摘要；日志仍不记录输入正文、响应正文或 API Key。
- 保持单一在途请求，没有并发多个模型请求；当前 NSURLSession 本身已异步，多模型并发会增加费用、429 和乱序风险。

### 验证证据

- make remote-completion-test：协议、取消、慢响应、错误分类、熔断、缓存命中和诊断字段测试均 PASS。
- make test app：既有输入、候选条、数据和严格构建全部通过；临时签名和验签通过。
- 逐文件 Clang Analyzer 检查 RemoteCompletionClient.m、Diagnostics.m、main.m，0 诊断。

### 阻塞与风险

- 远程模型服务器仍是端到端主要耗时，最近现场约 1.2～1.5 秒；本轮优化可减少本地等待和重复请求，但不能改变单次模型推理时间。
- 首次 Keychain 读取仍可能等待系统授权或安全服务响应，但等待发生在后台；日志会记录 prepare_finish 的耗时和错误，不会记录 Key。
- 若后台读取超过 2.5 秒，当前请求会结束准备阶段并等待下一次输入变化；晚到的成功结果只更新内存缓存，不会把旧建议插入当前草稿。
- 当前仍只显示一个最佳后缀，这是首版协议和交互约束；多候选需要改响应格式、候选切换和 Tab 语义，暂未与性能优化混在一起。

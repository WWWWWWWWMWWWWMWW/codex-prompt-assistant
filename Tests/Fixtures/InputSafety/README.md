# 无发送实机夹具

`index.html` 来自既有本地验收页；无表单、脚本、外部资源，CSP 禁止表单提交。收录及静态检查不等于实机通过。本轮仅修订步骤，不运行 UI。开始前检查 [当前阻断](../../../docs/status.md)；只用虚构内容，不为验收输入真实密码、消息或草稿。

## 准备与恢复边界

1. 记录应用版本、助手运行身份、助手/Codex/模型 PID 与启动时间。确认全局暂停关闭、模型可用。测试真无规则前的阳性对照必须使用独立、已有明确启用且无需改规则的合成输入场景（例如 TextEdit 新文稿），不能先启用本次 host。没有独立阳性证据时如实标缺失，不靠临时授权后恢复推荐冒充默认分支通过。敏感字段测试另需同一 host 的普通 textarea 阳性对照。
2. 手动运行 `python3 -m http.server 18765 --bind 127.0.0.1 --directory Tests/Fixtures/InputSafety`，打开 `http://127.0.0.1:18765/`。端口占用时停止，不杀未知进程。
3. 规则键为规范化 host `127.0.0.1`，不含端口/路径。换端口不构成新站点；同 host 的其他页面共用规则。先只读记录浏览器应用规则、该 host 是否存在存储规则、mode、searchExceptionEnabled、remoteCompletionAuthorized；不要记录不相关配置或凭据。
4. “无存储规则”与“显式推荐”分开。当前菜单选择推荐会保留搜索/远程位，不等于删除规则。没有安全删除单站点规则的 UI，因此不能用全量 defaults reset 造条件；未能证明无规则或无法恢复原不存在状态，就将该用例记未验证，改测显式规则用例。
5. 若 host 原无规则且没有精确恢复不存在状态的安全方法，本次只观察 UI-01；其他会写该 host 规则的用例跳过并记录原因。测后恢复完整原规则及原不存在状态。不能证明精确恢复时，不执行该规则变更用例；关闭仅自己创建的页面/文稿，停止仅本次启动的 HTTP 服务。

固定普通草稿：`请整理这次项目复盘的核查步骤，并保留待确认事项`。虚构敏感字段文本：`synthetic-only-12345`。

## 分开记录每个用例

| ID | 条件与操作 | 必需证据 / 判定边界 |
| --- | --- | --- |
| UI-01 真无规则默认拒绝 | 已只读证明 host 无存储规则，浏览器应用未整体关闭；先测试再做任何 host 变更 | 默认推荐拒绝、无候选、bodyRead=false；无法证明无规则则未验证，不能用关闭替代 |
| UI-02 显式推荐 | host 推荐，搜索/远程位明确关闭，输入普通草稿 | 推荐默认拒绝；验证规则切换后的行为，不代表无规则分支 |
| UI-03 显式关闭 | host 关闭，仍输入合成普通文本 | 关闭原因、旧候选立即清除，不能记成默认未授权通过 |
| UI-04 精确 host 启用普通输入 | host 启用，搜索例外关闭；输入固定草稿并停顿 | 出现候选后 Tab，读回新文本及差量；无合格候选可记录生成/质量原因，但 Tab 用例仍未完成 |
| UI-05 关闭再启用 | UI-04 已有阳性显示后关闭，保留同一非空合成草稿，不追加输入，再启用 | 关闭立即隐藏；同一 PID、同一文本下立即重查（观察请求/候选或明确质量拒绝证据）。编辑后才触发另记，不能计本项通过；不以重启解决 |
| UI-06 敏感字段 | 已有普通输入阳性对照；分别密码、验证码、支付、登录，使用虚构文本 | 对应保护原因、bodyRead=false、无候选；看不到读取证据时只能记可见行为，不得写零读取通过 |
| UI-07 搜索 | host 允许普通输入，分别关闭/开启搜索例外 | 关闭时保护；开启时仅本地；完成后恢复搜索位，不把允许搜索推广为其他敏感字段允许 |
| UI-08 主机未知 | 确认浏览器未取得 host 的实际场景 | 不允许配置/读取；本 HTML 不能强制制造未知 host，无对应现场就记未验证 |
| UI-09 空输入/占位符 | 清空自己创建的输入，确认 value/选区与占位符状态 | 无默认候选；不要因合法非空后缀有逗号而统一去掉所有标点 |

`bodyRead=false` 适用于有该诊断的通用路径。策略拒绝的离线读计数测试是另一层证据；二者分开记录，不能凭“没有显示”推出未读，也不能据浏览器结果证明 Codex 读前门禁已满足。

## TextEdit 与清理

只新建独立空白文稿，核对为空且属于本次测试，再输入固定草稿。推荐模式下验证显示、Tab、Esc、关闭/恢复和空输入；分别记录，不沿用浏览器的默认拒绝结论。若没有候选，先查状态，不因等待足够久就填通过。

输入前与清理前核对应用、窗口、焦点和合成草稿；Tab 后核对实际插入结果，绝不对不再符合预期的文本全选清空。焦点变化或出现用户编辑时停止清理，只保留待人工确认的测试窗口；不发送、不覆盖用户旧文稿。

结果使用 [验收模板](../../../docs/validation/TEMPLATE.md)，同时记录阳性对照、策略原因、读取证据、显示/插入结果、完整恢复结果和未验证项。多行、组合输入、中部光标、多屏、不同 Codex 任务属于另外的用例，不能因这一页通过而默认通过。
